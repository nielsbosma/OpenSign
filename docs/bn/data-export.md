# পূরণ করা ডেটা রপ্তানি

স্বাক্ষরকারীরা ফিল্ডে যা টাইপ করেন তা সিলমোহরকৃত PDF-এ থেকে যায়, আর আপনি সেটি ডেটা হিসেবেও বের করে নিতে পারেন: স্প্রেডশিট হিসেবে, JSON হিসেবে, API থেকে, অথবা MCP-র মাধ্যমে একটি AI এজেন্ট থেকে।

## অ্যাপ থেকে

**ডেটা রপ্তানি করুন** বেছে নিন, তারপর **Excel**, **CSV** বা **JSON**:

- **নথি** পৃষ্ঠায়, **নতুন নথি**-র পাশে। রপ্তানিতে থাকে তালিকা যে নথিগুলো দেখাচ্ছে সেগুলো: আপনার বেছে নেওয়া অবস্থার ট্যাব, ফোল্ডার, খোঁজ ও আর্কাইভ ট্যাব অনুযায়ী, শুধু যে পৃষ্ঠাটি দেখছেন সেটি নয়।
- **নথি** পৃষ্ঠায় সারি নির্বাচন করে, **কাজ**-এর অধীনে, শুধু সেই নথিগুলোর জন্য।
- একটি টেমপ্লেটে, **⋯** মেনুতে, এটি থেকে তৈরি প্রতিটি নথির জন্য।
- একটি বাল্ক পাঠানোতে, এটি যত নথি তৈরি করেছে সবগুলোর জন্য।
- একটি নথিতে, **⋯** মেনুতে, শুধু সেই একটি নথির জন্য।

একটি রপ্তানিতে সর্বোচ্চ 5,000টি নথি থাকে। বেশি রপ্তানি করতে ফিল্টার সংকীর্ণ করে কয়েক ভাগে করুন।

## এতে কী থাকে

একটি স্প্রেডশিটে প্রতিটি নথির জন্য একটি সারি থাকে, পুরোনোটি আগে:

| কলাম | |
| --- | --- |
| `Document ID`, `Title`, `Reference`, `Status` | নথিটি। `Reference` হলো আপনার **আপনার রেফারেন্স**। |
| `Created`, `Sent`, `Completed` | UTC-তে সময়। |
| `Party 1 Name`, `Party 1 Email`, `Party 1 Signed` | স্বাক্ষরের ক্রমে প্রতিটি পক্ষ, তারপর Party 2 এবং এভাবে। |
| প্রতিটি ফিল্ডের জন্য একটি কলাম | ফিল্ডের লেবেল অনুযায়ী নাম। |

ফিল্ডের মান OpenSign যেভাবে সংরক্ষণ করে সেভাবেই লেখা হয়, যাতে স্প্রেডশিটে সাজানো ও যোগ করা যায়:

| ফিল্ড | মান |
| --- | --- |
| সংখ্যা | `1234.5`-এর মতো একটি সাধারণ সংখ্যা, ফিল্ডের ডিসপ্লে ফরম্যাট যা-ই হোক। Excel-এ এটি আসল সংখ্যা। |
| সূত্র | সার্ভার যে সংখ্যা হিসাব করেছে, সংখ্যা ফিল্ডের মতোই। |
| তারিখ বাছাইকারী ও স্বাক্ষরের তারিখ | `YYYY-MM-DD`। |
| চেকবক্স | `true` বা `false`। Excel-এ আসল TRUE বা FALSE। |
| ড্রপডাউন ও রেডিও গ্রুপ | বেছে নেওয়া বিকল্প। একটি রেডিও গ্রুপ একটি কলাম, গ্রুপের লেবেল অনুযায়ী নাম। |
| একাধিক পছন্দ | বেছে নেওয়া বিকল্পগুলো, কমা দিয়ে আলাদা করা (JSON-এ একটি তালিকা)। |
| ফোন | দেশের কোডসহ নম্বর, যেমন `+46701234567`। |
| ছবি ও ফাইল আপলোড | ফাইলের নাম। ফাইলটি নিজে রপ্তানি হয় না; নথি থেকে ডাউনলোড করুন। |
| স্বাক্ষর | বাদ দেওয়া হয়: পক্ষের `Signed` কলাম বলে দেয় তিনি কখন স্বাক্ষর করেছেন। |

যে ফিল্ড এখনো পূরণ হয়নি তা খালি থাকে, তাই অপেক্ষমাণ নথিও রপ্তানি করা যায়। পক্ষ স্বাক্ষর করার সময় কোনো শর্তে লুকানো ফিল্ডও তা-ই।

### কলামের নাম

একটি কলামের নাম ফিল্ডের লেবেল অনুযায়ী হয়, অথবা লেবেল না থাকলে তার ধরন অনুযায়ী। পক্ষদের একই লেবেলের ফিল্ড থাকলে, যেমন প্রত্যেকের একটি করে নাম ফিল্ড, পক্ষটি যোগ হয়: `Name (Party 1)`, `Name (Party 2)`। একই পক্ষ দুবার একটি লেবেল ব্যবহার করলে একটি সংখ্যা যোগ হয়: `Note`, `Note (2)`। টেমপ্লেটে ফিল্ডগুলোকে স্পষ্ট, অনন্য লেবেল দিন, কলামগুলো তা অনুসরণ করবে।

ভিন্ন টেমপ্লেটের নথি রপ্তানি করলে প্রতিটি ফিল্ড লেবেল একটি কলাম হয়, এবং যে নথিতে সেই ফিল্ড নেই সেখানে তা খালি থাকে।

## নিরাপত্তা

- শুধু আপনি যে নথি দেখতে পারেন তা রপ্তানি হয়। যাঁদের সব নথিতে অ্যাক্সেস নেই তাঁরা নিজের নথি এবং তাঁদের সঙ্গে শেয়ার করা নথি রপ্তানি করেন।
- রপ্তানির জন্য `documents.export` অনুমতি লাগে, যা অ্যাডমিন, ম্যানেজার, প্রেরক ও অডিটরদের আছে। দর্শকরা নথির পৃষ্ঠায় শেয়ার করা নথির মান দেখতে পারেন, কিন্তু রপ্তানি করতে পারেন না। দেখুন [ব্যবহারকারী ও ভূমিকা](users-and-roles.md#permissions)।
- ব্যক্তিগত নম্বর কখনো রপ্তানি হয় না, এবং আপলোড করা ফাইল শুধু নাম দিয়ে তালিকাভুক্ত হয়।
- `=`, `+`, `-` বা `@` দিয়ে শুরু হওয়া CSV ঘরের আগে একটি `'` বসানো হয়, যাতে স্প্রেডশিট সেটিকে সূত্র হিসেবে না চালিয়ে টেক্সট হিসেবে দেখায়। নাহলে একজন স্বাক্ষরকারী ফিল্ডে `=HYPERLINK(…)` টাইপ করে আপনার কম্পিউটারে তা চালাতে পারতেন। ঋণাত্মক সংখ্যায় হাত দেওয়া হয় না। Excel ফাইল টেক্সটকে টেক্সট হিসেবেই লেখে, তাই সেখানে কিছু বদলাতে হয় না।
- CSV ফাইল বাইট অর্ডার মার্কসহ UTF-8, যাতে Excel å, ü ও 中 ঠিকভাবে দেখায়।
- প্রতিটি রপ্তানি [অডিট লগ](audit-log.md)-এ `documents.exported` হিসেবে লেখা হয়, ফরম্যাট, ফিল্টার এবং এতে থাকা নথিগুলোসহ।

## API থেকে

একটি নথির মান, টাইপসহ:

```sh
curl https://sign.example.com/api/v1/documents/$ID/values -H "Authorization: Bearer $KEY"
```

```json
{
  "id": "019a2b11-5d0e-7a42-b6f3-1c9e0d7a4f28",
  "title": "Lease, Storgatan 1",
  "status": "completed",
  "parties": [{ "id": "…", "slot": "Party 1", "role": "signer", "name": "Anna Berg", "email": "anna@example.com", "signedAt": "2026-10-29T10:12:00Z", "…": "…" }],
  "fields": [{ "key": "Monthly rent", "label": "Monthly rent", "kind": "number", "partyId": "…", "fieldIds": ["…"], "value": 12500 }],
  "values": { "Monthly rent": 12500, "Pets": "No", "Rooms": ["Kitchen", "Bath"], "Agree to terms": true }
}
```

`values` হলো সবচেয়ে দ্রুত পথ: ফিল্ড কী টাইপ করা মানের সঙ্গে মেলানো। `fields`-এ একই মান থাকে, সঙ্গে ফিল্ড আইডি, ধরন ও পক্ষ। মান পড়তে শুধু নথিতে অ্যাক্সেস লাগে, এবং নথি খোলার মতোই এটি অডিট হয় না।

একসাথে অনেক নথি:

```sh
curl -X POST https://sign.example.com/api/v1/exports -H "Authorization: Bearer $KEY" \
  -H "content-type: application/json" -d '{"format": "xlsx", "templateId": "…", "status": "completed"}'
```

বডিতে `format` (`csv`, `xlsx` বা `json`) এবং `ids`, `templateId`, `bulkId`, `status`, `search`, `folderId` ও `archived`-এর যেকোনোটি দেওয়া যায় (`archived`: শুধু আর্কাইভ করা নথির জন্য `true`, সেগুলো বাদ দিতে `false`, দুটোই চাইলে বাদ দিন)। উত্তরে থাকে `name`, `contentType` ও `count`, এবং CSV ও Excel-এর জন্য `contentBase64` অথবা JSON-এর জন্য `documents` (প্রতিটি ওপরের মতো)।

DocuSign ক্লায়েন্ট `GET /envelopes/{id}/form_data` থেকে একই মান পায়; দেখুন [DocuSign API](docusign.md)।

দুটি কলই MCP টুলও, `documents_values` ও `documents_export`, তাই একটি এজেন্ট জবাব দিতে পারে "এই মাসে কত ভাড়াটে পোষা প্রাণীর ব্যাপারে হ্যাঁ বলেছেন?" দেখুন [MCP](mcp.md)।

## ওয়েবহুকের সঙ্গে

`document.completed` ইভেন্টে একটি `valuesUrl` থাকে, অর্থাৎ ওপরের `/values` ঠিকানা, যাতে একটি ইন্টিগ্রেশন স্বাক্ষরকারীরা যা দিয়েছেন সব এক কলে আনতে পারে। ওয়েবহুক নিজে কখনো ফিল্ডের মান বহন করে না। দেখুন [ওয়েবহুক](webhooks.md#events)।
