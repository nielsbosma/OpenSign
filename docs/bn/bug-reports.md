# ত্রুটি জানানো

এমন কিছু পেয়েছেন যা কাজ করছে না? OpenSign-এর ভেতর থেকেই রিপোর্ট করুন। আপনার রিপোর্ট আপনার নিজের নামে GitHub-এ একটি পাবলিক issue হয়ে যায়, যাতে যাঁরা OpenSign তৈরি করেন তাঁরা আপনি যা দেখেছেন তা দেখতে পান।

## কীভাবে রিপোর্ট করবেন

1. সাইডবারের নিচে আপনার নামের নিচের মেনুটি খুলুন এবং **ত্রুটি জানান** বেছে নিন।
2. পৃষ্ঠার নিচে একটি প্যানেল খোলে। একটি টুল বেছে নিন:
   - **মন্তব্য**: একটি উপাদানে ক্লিক করুন, সেটিতে কী ভুল তা লিখুন এবং Enter চাপুন। সেটি একটি নম্বরযুক্ত বাক্স পায়।
   - **লুকান**: ব্যক্তিগত যেকোনো কিছুর উপর টেনে সেটি কালো করে দিন।
   - **বিরতি**: পৃষ্ঠাটি স্বাভাবিকভাবে ব্যবহার করুন, যেমন আগে একটি মেনু বা ডায়ালগ খুলতে। Esc চাপলেও বিরতি হয়।
3. কী ভুল হয়েছে এবং আপনি কী আশা করেছিলেন তা বর্ণনা করুন। শিরোনাম ঐচ্ছিক।
4. **রিপোর্ট পর্যালোচনা করুন** চাপুন। আপনি চূড়ান্ত স্ক্রিনশট এবং পাঠানো হবে এমন প্রতিটি লাইন দেখতে পান। যা শেয়ার করতে চান না তা বদলান বা সরান, অথবা স্ক্রিনশট বাদ দিন।
5. রিপোর্টটি পাবলিক হতে পারে তা নিশ্চিত করার বাক্সে টিক দিন, তারপর **GitHub-এ চালিয়ে যান** চাপুন।
6. ত্রুটির রিপোর্ট সার্ভিসে একটি নতুন উইন্ডো খোলে। সেটি রিপোর্টটি আরেকবার দেখায়। সেখানে GitHub দিয়ে সাইন ইন করে প্রকাশ করুন। এরপর উইন্ডোটি আপনার নতুন issue-এর লিংক দেয়।

আপনার অন্তত এক সপ্তাহ পুরোনো একটি GitHub অ্যাকাউন্ট লাগবে। আপনার ব্রাউজার নতুন উইন্ডোটি আটকালে OpenSign নিজে খোলার জন্য একটি লিংক দেখায়।

## কী প্রকাশিত হয়

issue-তে দেখা যায়:

- আপনার শিরোনাম ও বিবরণ, এবং আপনার মন্তব্যগুলো, প্রতিটি যে উপাদান নিয়ে সেটি সহ,
- স্ক্রিনশট, যদি আপনি রেখে থাকেন,
- একটি প্যাটার্ন হিসেবে পৃষ্ঠা, যেমন `/documents/:id`, OpenSign-এর সংস্করণ, আপনার ব্রাউজার ও সিস্টেম, উইন্ডোর আকার এবং অ্যাপের ভাষা,
- খোলা ডায়ালগের শিরোনাম, সাম্প্রতিক কনসোল ত্রুটি এবং সাম্প্রতিক ব্যর্থ অনুরোধ, যদি আপনি সেই লাইনগুলো রেখে থাকেন।

এতে কখনো আপনার OpenSign-এর ঠিকানা, পৃষ্ঠার আসল ঠিকানা, OpenSign-এ আপনার নাম বা ইমেইল ঠিকানা, বা কোনো নথির বিষয়বস্তু দেখা যায় না। প্রযুক্তিগত লাইনগুলো OpenSign ছাড়ার আগে ইমেইল ঠিকানা, ওয়েব ঠিকানা, আইডি, টোকেন, কী এবং লম্বা সংখ্যা হারায়; প্রতিটির জায়গায় `[removed]` বসে।

issue-টি আপনার GitHub অ্যাকাউন্ট দিয়ে তৈরি হয়, **OpenDeploy Bug Reports** অ্যাপের ব্যাজসহ, যেটি শুধু issue খুলতে পারে। সার্ভিসটি আপনার সাইন-ইন শুধু ওই একটি অনুরোধের জন্য ব্যবহার করে এবং তারপর তা বাতিল করে।

## স্ক্রিনশটে কী ঢাকা থাকে

স্ক্রিনশট নেওয়ার আগে OpenSign ধূসর রঙে ঢেকে দেয়:

- কোনো ফিল্ডে টাইপ করা সবকিছু,
- PDF পৃষ্ঠা ও থাম্বনেইল,
- পক্ষ ও ব্যবহারকারীদের নাম ও ইমেইল ঠিকানা,
- নথির শিরোনাম,
- অডিট ট্রেইলের এন্ট্রি,
- webhook ঠিকানা এবং API কী-র অনুমোদিত IP ঠিকানা।

**লুকান** দিয়ে আঁকা কালো বাক্সগুলোও ছবিতে স্থায়ীভাবে বসে যায়। পৃষ্ঠাটিতে নিজে কিছুই বদলায় না। পর্যালোচনার ধাপে স্ক্রিনশট দেখে নিন: অন্য যেকোনো ব্যক্তিগত কিছু লুকানো আপনার দায়িত্ব।

## স্ক্রিনশট সরানো

স্ক্রিনশট পাবলিক এবং কেউ না সরানো পর্যন্ত রাখা থাকে। প্রতিটি issue-এর শেষে থাকে **এই স্ক্রিনশট সরান**। সেটি খুলুন, GitHub দিয়ে সাইন ইন করুন, তাহলে ছবিটি মুছে যায় এবং issue-তে তা লেখা থাকে। আপনি নিজের স্ক্রিনশট সরাতে পারেন; রিপোজিটরির রক্ষণাবেক্ষণকারীরা যেকোনোটি সরাতে পারেন।

GitHub কিছু সময় ছবির ক্যাশ করা কপি রাখে, এবং যে কেউ সেটি সংরক্ষণ করে থাকতে পারে, তাই স্ক্রিনশট সরালে প্রতিটি কপি ফেরত নেওয়া যায় না। এ কারণেই পর্যালোচনার ধাপ আপনাকে পরীক্ষা করতে বলে যে স্ক্রিনে ব্যক্তিগত কিছু নেই।

## আপনার OpenSign থেকে কী বাইরে যায়

আপনি **GitHub-এ চালিয়ে যান** না চাপা পর্যন্ত কিছুই পাঠানো হয় না। তখন আপনার OpenSign-এর সার্ভার রিপোর্টটি `sliplane.opendeploy.cloud`-এ ত্রুটির রিপোর্ট সার্ভিসে পাঠায়, যেটি আপনি প্রকাশ না করা পর্যন্ত সর্বোচ্চ এক ঘণ্টা রাখে। OpenSign কোনো GitHub ক্রেডেনশিয়াল রাখে না।

প্রত্যেক ব্যক্তি ঘণ্টায় 10টি রিপোর্ট পাঠাতে পারেন, এবং একটি OpenSign ঘণ্টায় 30টি।

## অ্যাডমিনদের জন্য

ত্রুটির রিপোর্ট ডিফল্টভাবে চালু থাকে। **সেটিংস → ত্রুটির রিপোর্ট**-এ একজন অ্যাডমিন সেগুলো বন্ধ করতে পারেন, যাতে সবার জন্য **ত্রুটি জানান** লুকিয়ে যায়, অথবা রিপোর্ট অন্য কোনো রিপোজিটরিতে, যেমন একটি fork-এ, পাঠাতে পারেন। দেখুন [অ্যাডমিন সেটিংস](settings.md#bug-reports)। পাঠানো প্রতিটি রিপোর্ট অডিট ট্রেইলে লিপিবদ্ধ হয়।

বাইরের ইন্টারনেট অ্যাক্সেস ছাড়া কোনো ইনস্টলেশন রিপোর্ট পাঠাতে পারে না।
