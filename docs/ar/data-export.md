# تصدير البيانات المعبّأة

ما يكتبه الموقّعون في الحقول ينتهي في ملف PDF المختوم، ويمكنك أيضًا استخراجه كبيانات: كجدول بيانات، أو JSON، أو من API، أو من وكيل ذكاء اصطناعي عبر MCP.

## من التطبيق

اختر **تصدير البيانات**، ثم **Excel** أو **CSV** أو **JSON**:

- في صفحة **المستندات**، بجانب **مستند جديد**. يضم التصدير المستندات التي تعرضها القائمة: تبويب الحالة والمجلد والبحث وتبويب الأرشيف الذي اخترته، لا الصفحة التي تراها فقط.
- مع تحديد صفوف في صفحة **المستندات**، تحت **إجراءات**، لهذه المستندات فقط.
- في نموذج، من القائمة **⋯**، لكل مستند أُنشئ منه.
- في إرسال جماعي، لكل مستند أنشأه.
- في مستند، من القائمة **⋯**، لذلك المستند وحده.

يضم التصدير الواحد ما يصل إلى 5,000 مستند. ضيّق المرشحات لتصدير المزيد على أجزاء.

## ما الذي فيه

يضم جدول البيانات صفًا لكل مستند، الأقدم أولًا:

| الأعمدة | |
| --- | --- |
| Document ID وTitle وReference وStatus | المستند. Reference هو **مرجعك**. |
| Created وSent وCompleted | الأوقات بالتوقيت العالمي UTC. |
| Party 1 Name وParty 1 Email وParty 1 Signed | كل طرف بترتيب التوقيع، ثم Party 2 وهكذا. |
| عمود لكل حقل | يحمل اسم تسمية الحقل. |

تُكتب قيم الحقول بالطريقة التي يخزّنها بها OpenSign، فيمكن ترتيبها وجمعها في جدول بيانات:

| الحقل | القيمة |
| --- | --- |
| رقم | رقم بسيط، مثل `1234.5`، مهما كان تنسيق العرض للحقل. وفي Excel يكون رقمًا حقيقيًا. |
| صيغة | الرقم الذي حسبه الخادم، كما في حقل الرقم. |
| منتقي التاريخ وتاريخ التوقيع | `YYYY-MM-DD`. |
| مربع اختيار | `true` أو `false`. وفي Excel TRUE أو FALSE حقيقيتان. |
| القائمة المنسدلة ومجموعة أزرار الاختيار | الخيار المحدد. مجموعة أزرار الاختيار عمود واحد، يحمل اسم تسمية المجموعة. |
| الاختيار المتعدد | الخيارات المحددة، مفصولة بفواصل (قائمة في JSON). |
| الهاتف | الرقم مع رمز البلد، مثل `+46701234567`. |
| رفع صورة أو ملف | اسم الملف. لا يُصدَّر الملف نفسه؛ نزّله من المستند. |
| التوقيع | يُستبعد: يذكر عمود Signed للطرف وقت توقيعه. |

الحقل الذي لم يُملأ بعد يكون فارغًا، فيمكن تصدير المستندات قيد الانتظار أيضًا. وكذلك الحقل الذي أخفاه شرط عندما وقّع الطرف.

### أسماء الأعمدة

يحمل العمود اسم تسمية الحقل، أو اسم نوعه إن لم تكن له تسمية. وعندما يكون لأطراف حقول بالتسمية نفسها، مثل حقل Name لكل منهم، يُضاف الطرف: `Name (Party 1)` و`Name (Party 2)`. والتسمية المستخدمة مرتين من الطرف نفسه تحصل على رقم: `Note` و`Note (2)`. أعطِ الحقول في النموذج تسميات واضحة وفريدة وستتبعها الأعمدة.

وعند تصدير مستندات من نماذج مختلفة، تصبح كل تسمية حقل عمودًا، ويترك المستند الذي لا يحتوي ذلك الحقل خانته فارغة.

## الأمان

- لا تُصدَّر إلا المستندات التي يمكنك رؤيتها. ومن لا يملك وصولًا إلى كل المستندات يصدّر مستنداته الخاصة والمشاركة معه.
- يحتاج التصدير إلى الصلاحية `documents.export`، وهي لدى المسؤولين والمديرين والمرسلين والمدققين. يستطيع المشاهدون رؤية قيم المستند المشارك في صفحة المستند، لكن لا يستطيعون التصدير. راجع [المستخدمون والأدوار](users-and-roles.md#permissions).
- لا تُصدَّر الأرقام الشخصية أبدًا، وتُسرد الملفات المرفوعة بالاسم فقط.
- تحصل خلية CSV التي تبدأ بـ `=` أو `+` أو `-` أو `@` على `'` في أولها ليعرضها جدول البيانات كنص بدل تنفيذها كصيغة. وإلا لاستطاع موقّع أن يكتب `=HYPERLINK(…)` في حقل فيُنفَّذ على حاسوبك. وتُترك الأرقام السالبة كما هي. أما ملفات Excel فتكتب النص كنص، فلا حاجة لتغيير شيء فيها.
- ملفات CSV بترميز UTF-8 مع علامة ترتيب البايت (BOM)، ليعرض Excel الأحرف å وü و中 بشكل صحيح.
- يُكتب كل تصدير في [سجل التدقيق](audit-log.md) بالاسم `documents.exported`، مع الصيغة والمرشحات والمستندات التي ضمّها.

## من API

قيم مستند واحد، بأنواعها:

```sh
curl https://sign.example.com/api/v1/documents/$ID/values -H "Authorization: Bearer $KEY"
```

```json
{
  "id": "019a2b11-5d0e-7a42-b6f3-1c9e0d7a4f28",
  "title": "Lease, Storgatan 1",
  "status": "completed",
  "parties": [{ "id": "…", "slot": "Party 1", "role": "signer", "name": "Anna Berg", "email": "anna@example.com", "signedAt": "2026-10-29T10:12:00Z", "…": "…" }],
  "fields": [{ "key": "Monthly rent", "label": "Monthly rent", "kind": "number", "partyId": "…", "fieldIds": ["…"], "value": 12500 }],
  "values": { "Monthly rent": 12500, "Pets": "No", "Rooms": ["Kitchen", "Bath"], "Agree to terms": true }
}
```

`values` أسرع طريق: مفاتيح الحقول مرتبطة بقيم لها أنواعها. وتضم `fields` القيم نفسها مع معرّفات حقولها وأنواعها وأطرافها. تحتاج قراءة القيم إلى الوصول إلى المستند فقط، ولا تُسجَّل في التدقيق، مثل فتح المستند.

مستندات كثيرة دفعة واحدة:

```sh
curl -X POST https://sign.example.com/api/v1/exports -H "Authorization: Bearer $KEY" \
  -H "content-type: application/json" -d '{"format": "xlsx", "templateId": "…", "status": "completed"}'
```

يقبل الجسم `format` (`csv` أو `xlsx` أو `json`) وأيًا من `ids` و`templateId` و`bulkId` و`status` و`search` و`folderId` و`archived` (`true` للمستندات المؤرشفة فقط، و`false` لاستبعادها، وعند عدم ذكره تُضمّ كلتاهما). وتتضمن الإجابة `name` و`contentType` و`count`، إضافةً إلى `contentBase64` لـ CSV وExcel أو `documents` (كل منها كما سبق) لـ JSON.

يحصل عملاء DocuSign على القيم نفسها من `GET /envelopes/{id}/form_data`؛ راجع [DocuSign API](docusign.md).

والنداءان كلاهما أدوات MCP أيضًا، هما `documents_values` و`documents_export`، فيستطيع وكيل أن يجيب عن "كم مستأجرًا قال نعم للحيوانات الأليفة هذا الشهر؟" راجع [MCP](mcp.md).

## مع Webhooks

يحمل الحدث `document.completed` العنوان `valuesUrl`، وهو عنوان `/values` أعلاه، فيستطيع التكامل جلب كل ما أدخله الموقّعون في نداء واحد. أما Webhooks نفسها فلا تحمل قيم الحقول أبدًا. راجع [Webhooks](webhooks.md#events).
