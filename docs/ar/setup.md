# الإعداد الأول والبريد الإلكتروني

يقودك التثبيت الجديد عبر خطوتين قبل أن يتمكن أي شخص من استخدامه: إنشاء أول مسؤول، ثم ربط البريد الإلكتروني. إلى أن تكتمل الخطوتان، يعيد OpenSign كل مسؤول إلى صفحة الإعداد.

## الخطوة 1: أول مسؤول

عندما يبدأ OpenSign ولا يوجد فيه مستخدمون، يطبع في سجله **رمز إعداد** يُستخدم مرة واحدة:

```
No admin yet. Open https://sign.example.com and enter the setup code …
```

افتح التثبيت في المتصفح واملأ:

| الحقل | |
| --- | --- |
| رمز الإعداد | الرمز الموجود في السجل. يثبت أن لديك وصولًا إلى الخادم، فلا يستطيع من يعثر على تثبيت جديد على الإنترنت الاستيلاء عليه. |
| المؤسسة | اسم مؤسستك. يراه الموقّعون في رسائل البريد وعلى صفحة التوقيع. يمكنك تغييره لاحقًا من **الإعدادات ← المؤسسة**. |
| اسمك، البريد الإلكتروني، كلمة المرور | حساب المسؤول الخاص بك. |

التثبيتات التي تتم عبر زر **Deploy to Sliplane** تتخطى الرمز: ينشئ أداة النشر `SETUP_CODE`، ويؤدي **فتح OpenSign** في صفحتها الأخيرة إلى `/setup#code=…` الذي يملأه تلقائيًا. يقع الرمز في جزء الـ fragment من الرابط، وهو جزء لا يرسله المتصفح إلى أي خادم، وتزيله الصفحة من شريط العنوان. وإذا فتحت التثبيت بطريقة أخرى، فالرمز معروض في الصفحة الأخيرة من أداة النشر وفي بيئة الخدمة داخل Sliplane. وعند ضبط `SETUP_CODE` لا يطبع السجل رمزًا بعد ذلك.

بعد إنشاء أول مسؤول يتوقف رمز الإعداد عن العمل نهائيًا. ويُدعى بقية الأشخاص من **الإعدادات ← المستخدمون** (راجع [المستخدمون والأدوار](users-and-roles.md)).

## الخطوة 2: البريد الإلكتروني

يرسل OpenSign بالبريد الإلكتروني دعوات التوقيع والتذكيرات وإشعارات إيقاف المستند والمستندات المختومة ودعوات المستخدمين وروابط إعادة تعيين كلمات المرور. يطلب الإعداد مزوّد بريد يعمل، وهو Resend أو خادم SMTP الخاص بك، ويرسل إليك رسالة اختبار. لا ينتهي الإعداد إلا بعد أن يقبلها المزوّد، ولا يمكن إرسال المستندات بالبريد الإلكتروني قبل ذلك.

### Resend

[Resend](https://resend.com) هو المزوّد الافتراضي.

1. أنشئ حسابًا في Resend وتحقق من النطاق الذي تريد الإرسال منه ضمن **Domains**.
2. أنشئ مفتاح API ضمن **API Keys** بصلاحية الإرسال.
3. في OpenSign أدخل مفتاح API، و**عنوان المرسل** على النطاق الذي تم التحقق منه (مثل `sign@example.com`) و**اسم المرسل**.

### SMTP

اختر تبويب **خادم SMTP** أثناء الإعداد، أو **SMTP** في **المزوّد** ضمن **الإعدادات ← البريد الإلكتروني**، للإرسال عبر خادم البريد الخاص بك أو عبر مرحّل SMTP لمزوّد آخر.

| الحقل | |
| --- | --- |
| خادم SMTP | اسم المضيف، مثل `smtp.example.com`. بدون `smtp://` وبدون المنفذ. |
| المنفذ | عادةً 587 لـ STARTTLS أو 465 لـ TLS. |
| الأمان | **STARTTLS** أو **TLS**. |
| اسم المستخدم، كلمة المرور | اسم المستخدم الفارغ يرسل دون تسجيل دخول. تُخزَّن كلمة المرور مشفّرة. |
| عنوان المرسل، اسم المرسل | المرسل. |

يُشترط TLS دائمًا ويجب أن تكون الشهادة صالحة لاسم الخادم، فلا تنتقل بيانات الاعتماد دون تشفير أبدًا. لا يوجد خيار للنص الصريح. وتُرفض الخوادم الموجودة على الشبكات الخاصة، إلا في وضع التطوير.

### تغيير البريد لاحقًا

توجد إعدادات البريد في **الإعدادات ← البريد الإلكتروني**. تغيير المزوّد أو المفتاح أو خادم SMTP أو المرسل يمسح حالة "تم التحقق"، ويطلب OpenSign رسالة اختبار جديدة قبل أن تتمكن المستندات من الخروج مرة أخرى. حقل **الرد إلى** اختياري: إذا تُرك فارغًا تذهب الردود إلى الشخص الذي أرسل كل مستند.

## ما الذي يجب إعداده بعد ذلك

يتم باقي الإعداد كله في المتصفح، ضمن **الإعدادات**. لا شيء منه ضروري لبدء إرسال المستندات بروابط البريد الإلكتروني.

- **المؤسسة**: الاسم ورقم التسجيل والبلد والمنطقة الزمنية ولغة الموقّعين الافتراضية ولون العلامة والشعار. راجع [إعدادات المسؤول](settings.md).
- **الرسائل النصية**: لدعوات الرسائل النصية ورموز المرة الواحدة. راجع [إثبات الهوية](identification.md#sms-codes).
- **BankID والهوية الإلكترونية**: BankID السويدي وFreja eID وهويات إلكترونية شمالية أخرى. راجع [إثبات الهوية](identification.md).
- **التوقيع والختم**: اسم الختم والسبب وجهة الختم الزمني. راجع [ملفات PDF المختومة والأدلة](sealed-pdfs.md).
- **الأمان**: فرض تسجيل الدخول بخطوتين على الجميع. راجع [تسجيل الدخول ومفاتيح المرور والمصادقة الثنائية](account-security.md).
- **الذكاء الاصطناعي**: اختياري. راجع [مساعد الذكاء الاصطناعي والمراجعة](ai.md).

## تثبيت الإعدادات بمتغيرات البيئة

يمكن ضبط أي إعداد من إعدادات المسؤول بمتغير بيئة باسم `OPENSIGN_<GROUP>_<FIELD>`، مثل `OPENSIGN_EMAIL_API_KEY` أو `OPENSIGN_SECURITY_ENFORCE_TWO_FACTOR=true`. يُقفل الحقل المثبَّت في المتصفح ويظهر فيه "Set by an environment variable." وهذا مفيد للبنية التحتية ككود، ولإبقاء سر خارج قاعدة البيانات تمامًا. راجع [إعدادات المسؤول](settings.md#pinning-settings) للقائمة الكاملة بالأسماء.
