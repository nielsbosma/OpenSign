# الإرسال الجماعي

يرسل الإرسال الجماعي [نموذجًا](templates.md) إلى كل صف في جدول بيانات. يصبح كل صف مستندًا مستقلًا، بأطرافه وقيم حقوله، يُرسل ويُتتبع على حدة: عقد إيجار جديد لكل مستأجر، وتحديث سياسة لكل موظف.

## قبل أن تبدأ

- أعدّ نموذجًا فيه الأطراف والحقول والرسالة وإثبات الهوية الذي تريده.
- أعدّ ملف CSV أو Excel (`.xlsx`). احفظ ملفات `.xls` الأقدم وملفات OpenDocument `.ods` بصيغة `.xlsx` أولًا. يسمّي الصف الأول الأعمدة. حتى 1,000 صف و5 ميجابايت.
- تحتاج إلى صلاحية إرسال المستندات.

## الإرسال

1. افتح النموذج واختر **إرسال جماعي** من قائمته.
2. اختر الملف. يقرؤه OpenSign ويعرض كل عمود مع أول قيمة فيه وما **يملأ**ه.
3. راجع الربط. غيّر هدف أي عمود، أو اختر **تجاهل**.
4. اضبط اختياريًا **عناوين المستندات**، وهي نمط فيه أسماء الأعمدة بين أقواس معقوفة، مثل `Lease {Address}`. وإذا تُركت فارغة يُستخدم عنوان النموذج واسم الطرف الأول.
5. صحّح أي صفوف يسردها OpenSign تحت **صحّح هذه الصفوف قبل الإرسال**.
6. أرسل. ينشئ OpenSign المستندات ويرسلها في الخلفية ويفتح صفحة تقدم الإرسال الجماعي.

## ما الذي يمكن أن يملأه العمود

| الهدف | |
| --- | --- |
| الاسم أو البريد الإلكتروني أو الجوال أو الشركة أو الرقم الشخصي لطرف | مجموعة واحدة لكل طرف في النموذج. |
| حقل | أي حقل في النموذج له تسمية، يُملأ بوصفه قيمة المرسل لذلك الصف. يمكن كتابة الأرقام بأي من الطريقتين (`1 234,50` أو `1,234.50`)، والتواريخ بالصيغة YYYY-MM-DD أو بتنسيق الحقل، وحقول القوائم بنص الخيار، والاختيارات المتعددة مفصولة بفواصل. والقيمة التي تخالف فحوص الحقل تُفشل ذلك الصف. |
| العنوان | عنوان المستند، بدلًا من النمط. |
| مرجعك | المعرّف الخارجي للمستند، مثل رقم عميل. |
| اللغة لطرف | لغة رسائل ذلك الموقّع البريدية وصفحة توقيعه، برمز مثل `sv` أو `pt-BR`. راجع [صفحة التوقيع](signing-page.md#languages). |

## مطابقة الأعمدة

يطابق OpenSign الأعمدة بالاسم، بالإنجليزية والسويدية. فمثلًا "Email" و"E-post" و"Mail" كلها تطابق بريد الطرف الإلكتروني، و"Mobile" و"Mobil" و"Telefon" تطابق رقم الجوال. وعندما يكون للنموذج عدة أطراف، فإن العمود الذي يبدأ باسم الطرف، مثل "Guarantor email"، يذهب إلى ذلك الطرف.

إذا أعدّ المسؤول الذكاء الاصطناعي، فيمكنك أن تدعه يطابق الأعمدة التي لم تستطع القواعد المدمجة مطابقتها. يُرسل إليه أسماء الأعمدة. ويحصل أيضًا على بضعة صفوف نموذجية، لكن فقط إذا سمح المسؤول بإرسال نص المستندات إلى مزوّد الذكاء الاصطناعي. راجع [مساعد الذكاء الاصطناعي والمراجعة](ai.md).

## فحوص الصفوف

قبل إرسال أي شيء، يُفحص كل صف: يحتاج كل طرف إلى اسم، وعنوان بريد إلكتروني صالح إن كان يتلقى الرابط بالبريد، ورقم جوال صالح إن كان يتلقاه برسالة نصية، وهكذا. وإذا كان أي صف سيفشل، لا يُرسل شيء ويسرد OpenSign المشكلات برقم الصف في الجدول. صحّح الملف واختره من جديد.

## التقدم

تعرض صفحة الإرسال الجماعي كل صف مع مستلمه وحالته ورابط المستند الذي أنشأه. ويسرد **عمليات الإرسال الجماعي** في أسفل صفحة **النماذج** أحدث العمليات.

يتخطى **إيقاف** الصفوف التي لم تُرسل بعد. وتبقى المستندات المُرسلة بالفعل معروضة للتوقيع؛ ألغِها واحدًا واحدًا إذا لزم الأمر.

يُنزّل **تصدير البيانات** ما عبّأه كل مستلم، في صف لكل مستند، بصيغة Excel أو CSV أو JSON. راجع [تصدير البيانات المعبّأة](data-export.md).

## الخصوصية

تُخزَّن بيانات الصفوف مشفّرة أثناء الإرسال الجماعي، وتُحذف من كل صف بمجرد إرسال مستنده.

## من API

الإرسال الجماعي متاح عبر `POST /api/v1/bulk-sends/preview` (يقرأ ملفًا ويعطي ربطًا مقترحًا دون إرسال شيء) و`POST /api/v1/bulk-sends` (للإرسال). راجع [REST API](api.md#bulk-send).
