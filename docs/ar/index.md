# وثائق OpenSign

OpenSign خدمة توقيع إلكتروني مفتوحة المصدر تشغّلها بنفسك. ترفع مستندًا بصيغة Word أو PDF، وتضع الحقول، ثم ترسله. يحصل كل موقّع على رابط، ويُثبت هويته بالطريقة التي اخترتها، ثم يوقّع. وعندما ينتهي الجميع تحصل على ملف PDF مختوم يمكن لأي قارئ PDF التحقق منه، مع صفحات أدلة تسجّل من وقّع، ومتى، وكيف أثبت هويته.

تتبع هذه الوثائق لغتك، ويمكنك تغييرها من قائمة اللغة في الأعلى. الترجمات آلية والنسخة الإنجليزية هي المعتمدة.

تغطي هذه الصفحات كل أجزاء OpenSign، وهي موجّهة لمن يرسلون المستندات، وللمسؤولين الذين يديرون التثبيت، وللمطورين الذين يدمجونه مع أنظمتهم.

## ما الذي يقدمه OpenSign

- **مسارات التوقيع.** موقّعون وموافقون ومشاهدون، بترتيب محدد أو دفعة واحدة. تصل الروابط بالبريد الإلكتروني أو الرسائل النصية، أو تسلّمها أنت بنفسك، أو يوقّع الموقّع حضوريًا على جهازك. التذكيرات وتواريخ الانتهاء والرفض مع ذكر السبب كلها مدمجة. راجع [الأطراف والأدوار وترتيب التوقيع](parties.md).
- **إثبات الهوية.** رابط عبر البريد الإلكتروني، أو رمز عبر الرسائل النصية، أو BankID السويدي (باتفاقيتك الخاصة مع البنك أو عبر TIC Identity)، أو Freja eID، أو هويات إلكترونية شمالية أخرى عبر وسيط OpenID Connect. وعند إضافة رقم شخصي للطرف، لا يستطيع التوقيع إلا ذلك الشخص. راجع [إثبات الهوية](identification.md).
- **النماذج والإرسال الجماعي.** احفظ مستندًا جاهزًا كنموذج، ثم أرسله إلى كل صف في ملف CSV أو Excel. راجع [النماذج](templates.md) و[الإرسال الجماعي](bulk-send.md).
- **مرفقات الموقّعين.** اطلب من أحد الأطراف ملفات، مثل نسخة من الهوية، فتُنظَّف وتُختم داخل ملف PDF الموقّع. راجع [مرفقات الموقّعين](attachments.md).
- **ملفات PDF المختومة.** أختام PAdES B-LTA مع ختم زمني وفق RFC 3161 وكل ما يلزم للتحقق من الملف دون اتصال لسنوات. راجع [ملفات PDF المختومة والأدلة](sealed-pdfs.md).
- **المجلدات والأرشيف.** رتّب المستندات والنماذج في مجلدات مشتركة، وأرشف الأعمال المنتهية لتبقى القوائم قصيرة. راجع [المجلدات والأرشيف](folders.md).
- **الاحتفاظ والتحفظ القانوني.** احذف المستندات تلقائيًا بعد فترات محددة، واحتفظ بالمستندات المهمة بتحفظ قانوني. راجع [الاحتفاظ والتحفظ القانوني](retention.md).
- **المستخدمون والأدوار.** مسؤول ومدير ومرسل ومدقق ومشاهد، مع مفاتيح المرور أو تطبيق المصادقة لتسجيل الدخول بخطوتين. راجع [المستخدمون والأدوار](users-and-roles.md).
- **واجهات API.** REST API مع OpenAPI، ونقاط نهاية جاهزة للاستبدال المباشر لـ Scrive وDocuSign، وWebhooks موقّعة، وخادم MCP لـ Claude وعملاء الذكاء الاصطناعي الآخرين. راجع [REST API](api.md).
- **الذكاء الاصطناعي، إن أردته.** مساعد ومراجعة للمستندات قبل إرسالها. يبقى معطّلًا إلى أن يختار المسؤول مزوّدًا. راجع [مساعد الذكاء الاصطناعي والمراجعة](ai.md).
- **الأمان أولًا.** تشفير للبيانات المخزنة، وسجل تدقيق يكشف أي عبث، ورؤوس أمان صارمة للويب، وفحوصات صلاحيات على الخادم في كل استدعاء. راجع [نموذج الأمان](security.md).

## كيف تتكامل الأجزاء

OpenSign صورة حاوية واحدة. يحتاج إلى Postgres، وحاوية تخزين متوافقة مع S3، وإذا أردت قبول ملفات Word فمحوّل Gotenberg على شبكة خاصة. يعمل تطبيق الويب وواجهات API وخادم MCP والعامل الخلفي كلها في الصورة نفسها وتستخدم الخدمات نفسها، فيُطبَّق الإذن أو القاعدة بالطريقة نفسها مهما كانت طريقة وصول الطلب.

```
           ┌──────────────── one container ───────────────────────────┐
 browser ─▶│ React app ─ RPC ──┐                                      │
 REST/API ▶│ REST, Scrive,     ├─▶ services (permissions, audit, ──▶ Postgres
 Claude  ─▶│ DocuSign, MCP ────┤   settings, encryption)          ──▶ S3 (encrypted files)
 signer  ─▶│ signing page ─────┘   worker: email, SMS, sealing,   ──▶ Email, SMS, eID, TSA, LLM
           │                       webhooks, reminders            ──▶ Gotenberg (private)
           └──────────────────────────────────────────────────────────┘
```

OpenSign مرخّص برخصة MIT. الشيفرة المصدرية على [GitHub](https://github.com/nielsbosma/OpenSign).
