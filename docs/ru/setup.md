# Первая настройка и электронная почта

Прежде чем новой установкой смогут пользоваться, нужно сделать два шага: создать первого администратора и подключить электронную почту. Пока оба не выполнены, OpenSign возвращает каждого администратора на страницу настройки.

## Шаг 1: первый администратор

Когда OpenSign запускается и в нём нет пользователей, он выводит в журнал одноразовый **код настройки**:

```
No admin yet. Open https://sign.example.com and enter the setup code …
```

Откройте установку в браузере и заполните:

| Поле | |
| --- | --- |
| Код настройки | Код из журнала. Он подтверждает, что у вас есть доступ к серверу, поэтому тот, кто найдёт свежую установку в интернете, не сможет её занять. |
| Организация | Название вашей организации. Подписанты видят его в письмах и на странице подписания. Позже его можно изменить в **Настройки → Организация**. |
| Ваше имя, Эл. почта, Пароль | Ваша учётная запись администратора. |

Установки через кнопку **Deploy to Sliplane** обходятся без кода: установщик создаёт `SETUP_CODE`, а **Открыть OpenSign** на его завершающей странице ведёт на `/setup#code=…`, и код подставляется сам. Код находится во фрагменте URL, который браузер никогда не отправляет на сервер, а страница убирает его из адресной строки. Если вы открываете установку другим способом, код показан на завершающей странице установщика и в переменных окружения сервиса в Sliplane. Если задан `SETUP_CODE`, код в журнал больше не выводится.

Как только первый администратор создан, код настройки навсегда перестаёт действовать. Остальных приглашают в **Настройки → Пользователи** (см. [Пользователи и роли](users-and-roles.md)).

## Шаг 2: электронная почта

OpenSign отправляет по электронной почте приглашения на подписание, напоминания, уведомления об остановке документа, запечатанные документы, приглашения пользователей и сбросы паролей. Мастер настройки просит указать работающего почтового провайдера, Resend или собственный SMTP-сервер, и отправляет вам тестовое сообщение. Настройка завершается, только когда провайдер его принял, а до этого документы по электронной почте отправлять нельзя.

### Resend

[Resend](https://resend.com) — провайдер по умолчанию.

1. Создайте учётную запись Resend и подтвердите домен, с которого хотите отправлять, в разделе **Domains**.
2. Создайте ключ API в разделе **API Keys** с правом отправки.
3. В OpenSign введите ключ API, **Адрес отправителя** на подтверждённом домене (например, `sign@example.com`) и **Имя отправителя**.

### SMTP

Выберите вкладку **SMTP-сервер** во время настройки или **SMTP** в поле **Провайдер** в **Настройки → Эл. почта**, чтобы отправлять через собственный почтовый сервер или SMTP-ретранслятор другого провайдера.

| Поле | |
| --- | --- |
| SMTP-сервер | Имя хоста, например `smtp.example.com`. Без `smtp://` и без порта. |
| Порт | Обычно 587 для STARTTLS или 465 для TLS. |
| Безопасность | **STARTTLS** или **TLS**. |
| Имя пользователя, Пароль | Если имя пользователя пусто, письма отправляются без входа. Пароль хранится в зашифрованном виде. |
| Адрес отправителя, Имя отправителя | Отправитель. |

TLS требуется всегда, а сертификат должен быть действителен для имени сервера, поэтому учётные данные никогда не передаются без шифрования. Варианта без шифрования нет. Серверы в частных сетях отклоняются, кроме режима разработки.

### Как изменить почту позже

Настройки почты находятся в **Настройки → Эл. почта**. Смена провайдера, ключа, SMTP-сервера или отправителя сбрасывает состояние «подтверждено», и OpenSign снова попросит тестовое письмо, прежде чем документы смогут уходить. **Адрес для ответа** необязателен: если он пуст, ответы приходят тому, кто отправил документ.

## Что настроить дальше

Вся остальная настройка выполняется в браузере, в разделе **Настройки**. Для отправки документов по ссылкам из писем она не нужна.

- **Организация**: название, регистрационный номер, страна, часовой пояс, язык подписантов по умолчанию, фирменный цвет и логотип. См. [Настройки администратора](settings.md).
- **SMS**: для приглашений по SMS и одноразовых кодов. См. [Идентификация](identification.md#sms-codes).
- **BankID и eID**: шведский BankID, Freja eID и другие скандинавские eID. См. [Идентификация](identification.md).
- **Подписание и печать**: название печати, причина и центр меток времени. См. [Запечатанные PDF и доказательства](sealed-pdfs.md).
- **Безопасность**: требовать двухфакторный вход от всех. См. [Вход, ключи доступа и двухфакторная аутентификация](account-security.md).
- **ИИ**: необязательно. См. [ИИ-ассистент и проверка](ai.md).

## Закрепление настроек переменными окружения

Любую настройку администратора можно задать переменной окружения с именем `OPENSIGN_<GROUP>_<FIELD>`, например `OPENSIGN_EMAIL_API_KEY` или `OPENSIGN_SECURITY_ENFORCE_TWO_FACTOR=true`. Закреплённое поле блокируется в браузере и показывает «Задано переменной окружения.» Это удобно для инфраструктуры как кода и для того, чтобы вообще не хранить секрет в базе данных. Полный список имён см. в разделе [Настройки администратора](settings.md#pinning-settings).
