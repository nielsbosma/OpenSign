# Идентификация

Для каждого участника вы выбираете, насколько надёжно он должен подтвердить свою личность, отдельно для открытия документа (**Идентификация для просмотра**) и для его подписания (**Идентификация для подписания**). Что бы он ни использовал, это записывается в журнал аудита и на страницы доказательств запечатанного PDF.

## Способы

| Способ | Для просмотра | Для подписания | Что нужно |
| --- | --- | --- | --- |
| **Нет** | По умолчанию | | Для открытия документа достаточно ссылки. |
| **Стандартная** | | По умолчанию | Ссылка. Типично для доставки по электронной почте и SMS, так как ссылку получает только адресат. |
| **Код из SMS** (`sms_pin`) | Да | Да | SMS-провайдер и мобильный номер участника. |
| **Шведский BankID** (`se_bankid`) | Да | Да | BankID напрямую или через TIC Identity. |
| **Freja eID** (`freja`) | Да | Да | Договор с Freja eID. |
| **Другой eID** (`broker`) | Да | Да | Брокер eID на основе OpenID Connect, например Idura (Criipto) или Signicat. |

Способ, не настроенный в этой установке, показывается в диалоге участника недоступным. Отправка отклоняется, если участник использует неготовый способ, поэтому подписант никогда не застрянет.

## Фото с веб-камеры

Отметьте **Запросить идентификацию по веб-камере** у подписанта или согласующего. Перед подписанием он делает своё живое фото камерой компьютера или телефона: **Включить камеру**, **Сделать фото**, затем **Использовать фото** или **Переснять**. Выбора файла нет.

- С фото удаляются данные EXIF и геолокации, оно хранится в зашифрованном виде и встраивается в запечатанный PDF вместе с хешем SHA-256. Журнал аудита фиксирует, когда оно было сделано.
- На странице документа карточка участника показывает фото и время съёмки. Каждый просмотр записывается в журнал аудита.
- Камерой может пользоваться только страница подписания. Все остальные страницы OpenSign её блокируют.

Фото — это свидетельство о том, кто подписал, а не доказательство «живости»: опытный подписант может отправить неподвижное изображение вместо живого. Для надёжной идентификации используйте eID.

## Личные номера

Для BankID и Freja укажите у участника **Личный номер**. Тогда OpenSign требует, чтобы eID называл именно этого человека: идентификация кем-либо другим отклоняется и записывается в журнал аудита. Без личного номера подписать мог бы любой, у кого есть ссылка и eID, и проверка настройки предупреждает об этом.

Личный номер хранится в зашифрованном виде и показывается маскированным (только последние четыре цифры), в том числе в запечатанном PDF, который получает каждый участник. Полный номер, который вернул eID, остаётся в базе данных зашифрованным. При редактировании участника оставьте поле пустым, чтобы сохранить хранящийся номер.

## Идентификация для просмотра и для подписания

**Идентификация для просмотра** и **Идентификация для подписания** — два отдельных шага, даже при одном и том же eID. Только идентификация, выполненная для подписания, сообщает человеку, что именно он подписывает (BankID показывает это в приложении), поэтому участник с обоими способами идентифицируется дважды.

## Коды из SMS

Участник запрашивает код на странице подписания и получает 6-значный код по SMS.

- Код действует 10 минут, на него даётся 5 попыток.
- Одному участнику можно отправить не более 5 кодов в час.
- Коды хранятся только в виде хеша с ключом.
- В запечатанном PDF номер телефона показан только тремя последними цифрами.

### Настройка SMS

В **Настройки → SMS** выберите провайдера:

| Провайдер | Имя пользователя | Пароль |
| --- | --- | --- |
| [46elks](https://46elks.com) | Имя пользователя API | Пароль API |
| [Twilio](https://www.twilio.com) | Account SID | Auth token |

**Отправитель** — это имя до 11 букв или принадлежащий вам номер. Тот же провайдер используется для доставки ссылок для подписания по SMS.

### Ограничение расходов на SMS

Текстовые сообщения стоят денег, а по ссылкам общего доступа их могут запрашивать незнакомые вам люди. Эти настройки ограничивают счёт:

- **Разрешённые страны**: телефонные коды стран, на которые разрешено отправлять SMS, например `46, 47`. Пусто разрешает все страны; именно так начинается установка, чтобы ничего из уже работающего не остановилось. Задайте страны, в которые вы действительно отправляете: некоторые зарубежные номера стоят во много раз дороже местных.
- **Сообщений в час** (по умолчанию 200) и **Сообщений в день** (1000): для всего, что отправляет установка. Когда лимит достигнут, дальнейшие сообщения отклоняются, пока не пройдёт окно, а сервер записывает в журнал предупреждение.
- **Сообщений в час для ссылки общего доступа** (30): для всех документов, созданных из одной ссылки общего доступа.

0 означает отсутствие лимита.

## Шведский BankID

Подписант идентифицируется в приложении BankID: на том же устройстве с помощью **Открыть BankID на этом устройстве** или сканируя QR-код с помощью **BankID на другом устройстве**. Если у участника есть личный номер, ответить может только BankID этого человека.

Подключить BankID можно двумя способами. В любом случае участники выбирают «Шведский BankID».

### По собственному договору с BankID

1. В **Настройки → BankID и eID** включите **Шведский BankID**.
2. Чтобы попробовать, включите **Использовать тестовую среду BankID** и оставьте сертификат пустым. OpenSign использует публичный тестовый сертификат BankID, и вы сможете подписывать с [тестовым BankID](https://developers.bankid.com/test-portal).
3. Для боевой среды отключите тестовую среду и загрузите сертификат доверяющей стороны, который вам выдал банк (файл `.p12`), вместе с паролем.

OpenSign обращается к BankID по взаимному TLS и доверяет только собственному корневому сертификату BankID, который встроен. Заменяйте его в **Корневой сертификат сервера BankID** только если об этом сообщит BankID.

### Через TIC Identity

[TIC Identity](https://id.tic.io) предлагает BankID без собственного договора с банком.

1. В портале TIC включите OpenID Connect для своего тенанта и зарегистрируйте `https://<your-install>/api/eid/callback` как URI перенаправления.
2. В **Настройки → BankID и eID** включите **BankID через TIC Identity** и введите имя тенанта (как в `https://id.tic.io/<tenant>`), **ID клиента** и **Секрет клиента**.

TIC используется всегда, когда BankID со своим сертификатом выключен. OpenSign доверяет только шведскому личному номеру из утверждения `nin` у TIC и требует, чтобы он был действительным.

## Freja eID

1. В **Настройки → BankID и eID** включите **Freja eID**. Пока вы тестируете, используйте **Использовать тестовую среду Freja**.
2. Загрузите **Сертификат клиента** от Freja (файл `.pfx`) вместе с паролем.
3. Добавьте **Сертификат подписи результатов Freja**. OpenSign отклоняет любой результат, подпись которого с ним не сходится.

Подписант подтверждает в приложении Freja.

## Другие скандинавские eID через брокера

Брокер OpenID Connect, например Idura (Criipto) или Signicat, даёт доступ к норвежскому и датскому BankID, MitID, финским банковским идентификаторам и другим.

1. Создайте приложение у брокера и зарегистрируйте `https://<your-install>/api/eid/callback` как URI перенаправления.
2. В **Настройки → BankID и eID** включите **Брокер eID (OpenID Connect)** и введите **URL издателя**, **ID клиента** и **Секрет клиента**.
3. По желанию задайте **Выбор eID (acr_values)**, чтобы выбрать один eID, например `urn:grn:authn:no:bankid`. Если пусто, подписант выбирает у брокера.

Подписанта отправляют к брокеру и обратно. OpenSign использует поток кода авторизации с PKCE, state и nonce и проверяет подпись, эмитента, адресата и срок действия ID-токена.

Идентификация должна завершиться в том браузере, где началась: две части связывает короткоживущий cookie, это верно и для TIC Identity, а ответ, вернувшийся в другое место, отклоняется и записывается в журнал аудита. Оставьте cookie включёнными для адреса вашего OpenSign.

Если страница подписания встроена в другой сайт, из фрейма cookie установить нельзя. Тогда подписант получает окно на адресе вашего OpenSign, где сказано, для какого документа выполняется идентификация, и переходит к брокеру, нажав кнопку. Это предлагается только участникам с доставкой по ссылке в установке, где разрешено встраивание.

## Что записывается

Для каждой идентификации OpenSign сохраняет способ, имя и (маскированный) личный номер, которые вернул eID, время, IP-адрес и браузер. Данные eID хранятся в зашифрованном виде. Они появляются в журнале аудита и на страницах доказательств запечатанного PDF. См. [Запечатанные PDF и доказательства](sealed-pdfs.md).
