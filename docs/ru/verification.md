# Проверка документа

Каждый, у кого есть подписанный PDF, может проверить, что он подлинный и не изменён. Учётная запись не нужна.

## На странице проверки

Откройте `https://<your-install>/verify` (на неё также ведёт **Проверить документ** на боковой панели приложения, она указана и на страницах доказательств каждого запечатанного документа) и перетащите PDF.

Файл проверяется на сервере и не сохраняется. Страница отвечает на два вопроса:

1. **Запечатала ли эта установка именно этот файл?** «Sealed by this OpenSign» с названием документа и временем завершения означает, что SHA-256 файла совпадает с документом, который запечатал этот сервер, и печать цела, поставленная одним из сертификатов печати этого сервера. «Not a document this server sealed» означает, что файл изменили после запечатывания или он получен из другого места.
2. **Целы ли подписи?** Каждая подпись и метка времени в файле перечисляются с указанием, кто их поставил, когда и цела ли она. Цела означает лишь то, что байты такие, как были подписаны: любой может создать сертификат с любым именем. Подпись, которая цела, но поставлена не этим сервером, сообщает об этом, а имя на ней не подтверждено.

## Что охватывает проверка

Для каждой подписи и метки времени документа в файле OpenSign проверяет:

- что криптография подписи корректна и охватывает те байты, которые она заявляет,
- охватывает ли она весь файл или только более раннюю ревизию,
- является ли всё, добавленное после неё, только данными проверки: хранилищем безопасности документа с сертификатами и ответами об отзыве и невидимыми метками времени документа,
- собственную подпись центра меток времени (RSA от 2048 бит, ECDSA P-256 и P-384, SHA-2), что его сертификат предназначен для меток времени и что он был действителен в момент метки. Метка времени, не прошедшая эти проверки, не показывает времени.

Любое другое изменение после подписи, например новая аннотация, правка формы, изменённая запись каталога, удалённый объект или новый объект, который, судя по всему, никем не используется, помечает эту подпись как нецелую. Так же действует обновление, записанное не простым способом, которым OpenSign записывает свои. Это закрывает распространённый приём изменения подписанного PDF инкрементным обновлением, которое некоторые программы не отмечают, и означает, что файл, в который другой инструмент добавил данные проверки, может показываться как изменённый.

OpenSign не сверяет подписавших и центры меток времени со списком доверия. Для этого используйте программу для чтения PDF, у которой он есть.

## В программе для чтения PDF

Запечатанные документы — это стандартные файлы PAdES, поэтому Adobe Acrobat, Foxit и другие программы, понимающие подписи, показывают печать, метку времени и то, изменился ли документ. Поскольку сертификат печати по умолчанию самоподписанный, программа может сообщить, что не знает личность подписавшего; страница проверки выше — авторитетная проверка для вашей установки. См. [Запечатанные PDF и доказательства](sealed-pdfs.md#the-seal-certificate).

## Через API

`POST /api/v1/verify` с необработанным PDF в теле (до 40 МБ) возвращает тот же результат в виде JSON. Ключ API не нужен, частота запросов ограничивается по адресу. См. [REST API](api.md).

```sh
curl -X POST https://sign.example.com/api/v1/verify \
  -H "Content-Type: application/pdf" --data-binary @signed.pdf
```
