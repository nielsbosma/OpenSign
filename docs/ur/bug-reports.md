# خرابی کی اطلاع دینا

کوئی ایسی چیز ملی جو کام نہیں کرتی؟ OpenSign کے اندر سے ہی اس کی رپورٹ کریں۔ آپ کی رپورٹ آپ کے اپنے نام سے GitHub پر ایک عوامی issue بن جاتی ہے، تاکہ OpenSign بنانے والے لوگ وہی دیکھ سکیں جو آپ نے دیکھا۔

## رپورٹ کیسے کریں

1. سائیڈبار کے نیچے اپنے نام کے نیچے والا مینو کھولیں اور **خرابی کی اطلاع دیں** چنیں۔
2. صفحے کے نیچے ایک پینل کھلتا ہے۔ ایک ٹول چنیں:
   - **تبصرہ**: کسی عنصر پر کلک کریں، بتائیں کہ اس میں کیا غلط ہے، اور Enter دبائیں۔ اسے ایک نمبر والا خانہ مل جاتا ہے۔
   - **چھپائیں**: کسی بھی نجی چیز پر کھینچیں تاکہ وہ سیاہ ہو جائے۔
   - **روکیں**: صفحہ معمول کے مطابق استعمال کریں، مثلاً پہلے کوئی مینو یا ڈائیلاگ کھولنے کے لیے۔ Esc سے بھی رک جاتا ہے۔
3. بتائیں کہ کیا غلط ہوا اور آپ کیا توقع کر رہے تھے۔ عنوان اختیاری ہے۔
4. **رپورٹ کا جائزہ لیں** دبائیں۔ آپ کو حتمی اسکرین شاٹ اور بھیجی جانے والی ہر سطر نظر آتی ہے۔ جو کچھ آپ شیئر نہیں کرنا چاہتے اسے بدلیں یا ہٹائیں، یا اسکرین شاٹ شامل نہ کریں۔
5. وہ خانہ منتخب کریں جو تصدیق کرتا ہے کہ رپورٹ عوامی ہو سکتی ہے، پھر **GitHub پر جاری رکھیں** دبائیں۔
6. خرابی کی رپورٹ سروس پر ایک نئی ونڈو کھلتی ہے۔ وہ رپورٹ ایک بار پھر دکھاتی ہے۔ وہاں GitHub سے سائن ان کریں اور اسے شائع کریں۔ اس کے بعد ونڈو آپ کے نئے issue کا لنک دیتی ہے۔

آپ کو کم از کم ایک ہفتہ پرانا GitHub اکاؤنٹ چاہیے۔ اگر آپ کا براؤزر نئی ونڈو روک دے تو OpenSign اسے خود کھولنے کے لیے ایک لنک دکھاتا ہے۔

## کیا شائع ہوتا ہے

issue میں دکھائی دیتا ہے:

- آپ کا عنوان اور تفصیل، اور آپ کے تبصرے، ہر ایک اس عنصر کے ساتھ جس کے بارے میں وہ ہے،
- اسکرین شاٹ، اگر آپ نے اسے رکھا،
- صفحہ ایک پیٹرن کے طور پر، جیسے `/documents/:id`، OpenSign کا ورژن، آپ کا براؤزر اور سسٹم، ونڈو کا سائز اور ایپ کی زبان،
- کھلے ڈائیلاگ کے عنوانات، حالیہ کنسول خرابیاں اور حالیہ ناکام درخواستیں، اگر آپ نے وہ سطریں رکھیں۔

اس میں کبھی آپ کے OpenSign کا پتا، صفحے کا اصل پتا، OpenSign میں آپ کا نام یا ای میل پتا، یا کسی دستاویز کا مواد نظر نہیں آتا۔ تکنیکی سطروں سے OpenSign چھوڑنے سے پہلے ای میل پتے، ویب پتے، ID، ٹوکن، کلیدیں اور لمبے نمبر ہٹا دیے جاتے ہیں؛ ہر ایک کی جگہ `[removed]` آ جاتا ہے۔

issue آپ کے GitHub اکاؤنٹ سے بنتا ہے، **OpenDeploy Bug Reports** ایپ کے بیج کے ساتھ، جو صرف issue کھول سکتی ہے۔ سروس آپ کا سائن اِن صرف اسی ایک درخواست کے لیے استعمال کرتی ہے اور پھر اسے منسوخ کر دیتی ہے۔

## اسکرین شاٹ میں کیا ڈھکا جاتا ہے

اسکرین شاٹ لینے سے پہلے OpenSign انہیں سرمئی رنگ سے ڈھک دیتا ہے:

- کسی فیلڈ میں ٹائپ کی گئی ہر چیز،
- PDF صفحات اور تھمب نیل،
- فریقین اور صارفین کے نام اور ای میل پتے،
- دستاویزات کے عنوانات،
- آڈٹ ٹریل کے اندراجات،
- webhook پتے اور API کلیدوں کے اجازت یافتہ IP پتے۔

**چھپائیں** سے بنائے گئے سیاہ خانے بھی تصویر میں مستقل طور پر شامل ہو جاتے ہیں۔ خود صفحے پر کچھ نہیں بدلتا۔ جائزے کے مرحلے میں اسکرین شاٹ دیکھ لیں: باقی کوئی بھی نجی چیز چھپانا آپ کی ذمہ داری ہے۔

## اسکرین شاٹ ہٹانا

اسکرین شاٹ عوامی ہوتے ہیں اور تب تک رکھے جاتے ہیں جب تک کوئی انہیں ہٹا نہ دے۔ ہر issue کے آخر میں **یہ اسکرین شاٹ ہٹائیں** ہوتا ہے۔ اسے کھولیں، GitHub سے سائن ان کریں، تو تصویر حذف ہو جاتی ہے اور issue میں یہ لکھا آ جاتا ہے۔ آپ اپنے اسکرین شاٹ ہٹا سکتے ہیں؛ ریپوزٹری کے مینٹینرز کوئی بھی ہٹا سکتے ہیں۔

GitHub تصویروں کی کیش شدہ کاپیاں کچھ عرصے تک رکھتا ہے، اور کوئی بھی اسے محفوظ کر چکا ہو سکتا ہے، اس لیے اسکرین شاٹ ہٹانے سے ہر کاپی واپس نہیں لی جا سکتی۔ اسی لیے جائزے کا مرحلہ آپ سے یہ جانچنے کو کہتا ہے کہ اسکرین پر کچھ بھی نجی نہ ہو۔

## آپ کے OpenSign سے کیا باہر جاتا ہے

جب تک آپ **GitHub پر جاری رکھیں** نہیں دباتے، کچھ نہیں بھیجا جاتا۔ تب آپ کے OpenSign کا سرور رپورٹ `sliplane.opendeploy.cloud` پر خرابی کی رپورٹ سروس کو بھیجتا ہے، جو آپ کے شائع کرنے تک اسے زیادہ سے زیادہ ایک گھنٹہ رکھتی ہے۔ OpenSign کے پاس GitHub کی کوئی اسناد نہیں ہوتیں۔

ہر شخص ایک گھنٹے میں 10 رپورٹیں بھیج سکتا ہے، اور ایک OpenSign ایک گھنٹے میں 30۔

## ایڈمنز کے لیے

خرابی کی رپورٹس بطورِ طے شدہ آن ہوتی ہیں۔ **ترتیبات ← خرابی کی رپورٹس** میں ایڈمن انہیں بند کر سکتا ہے، جس سے **خرابی کی اطلاع دیں** سب کے لیے چھپ جاتا ہے، یا رپورٹیں کسی دوسری ریپوزٹری، جیسے کسی fork، میں بھیج سکتا ہے۔ دیکھیں [ایڈمن ترتیبات](settings.md#bug-reports)۔ بھیجی گئی ہر رپورٹ آڈٹ ٹریل میں درج ہوتی ہے۔

بیرونی انٹرنیٹ رسائی کے بغیر انسٹالیشن رپورٹیں نہیں بھیج سکتی۔
