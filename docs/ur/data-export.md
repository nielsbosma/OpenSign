# بھرے ہوئے ڈیٹا کی ایکسپورٹ

دستخط کنندگان فیلڈز میں جو ٹائپ کرتے ہیں وہ مہر شدہ PDF میں چلا جاتا ہے، اور آپ اسے ڈیٹا کے طور پر بھی نکال سکتے ہیں: اسپریڈ شیٹ کی شکل میں، JSON کے طور پر، API سے، یا MCP کے ذریعے کسی AI ایجنٹ سے۔

## ایپ سے

**ڈیٹا ایکسپورٹ کریں** منتخب کریں، پھر **Excel**، **CSV** یا **JSON**:

- **دستاویزات** کے صفحے پر، **نئی دستاویز** کے ساتھ۔ ایکسپورٹ میں وہ دستاویزات ہوتی ہیں جو فہرست دکھاتی ہے: آپ کا چنا ہوا حیثیت کا ٹیب، فولڈر، تلاش اور آرکائیو ٹیب، صرف وہ صفحہ نہیں جو آپ دیکھ رہے ہیں۔
- **دستاویزات** کے صفحے پر قطاریں منتخب کر کے، **کارروائیاں** کے تحت، صرف انہی دستاویزات کے لیے۔
- ٹیمپلیٹ پر، **⋯** مینو میں، اس سے بنی ہر دستاویز کے لیے۔
- بلک بھیجنے پر، اس کی بنائی ہر دستاویز کے لیے۔
- دستاویز پر، **⋯** مینو میں، اسی ایک دستاویز کے لیے۔

ایک ایکسپورٹ میں 5,000 دستاویزات تک ہو سکتی ہیں۔ مزید ایکسپورٹ کرنے کے لیے فلٹرز محدود کر کے حصوں میں کریں۔

## اس میں کیا ہوتا ہے

اسپریڈ شیٹ میں ہر دستاویز کی ایک قطار ہوتی ہے، سب سے پرانی پہلے۔ کالموں کے نام ایکسپورٹ فائل میں جوں کے توں انگریزی میں لکھے جاتے ہیں:

| کالمز | |
| --- | --- |
| Document ID, Title, Reference, Status | دستاویز۔ Reference آپ کا **آپ کا حوالہ** ہے۔ |
| Created, Sent, Completed | UTC میں اوقات۔ |
| Party 1 Name, Party 1 Email, Party 1 Signed | ہر فریق دستخطی ترتیب میں، پھر Party 2 اور اسی طرح۔ |
| ہر فیلڈ کا ایک کالم | فیلڈ کے لیبل کے نام پر۔ |

فیلڈ کی قدریں اسی طرح لکھی جاتی ہیں جیسے OpenSign انہیں محفوظ کرتا ہے، تاکہ اسپریڈ شیٹ میں انہیں ترتیب دیا اور جمع کیا جا سکے:

| فیلڈ | قدر |
| --- | --- |
| نمبر | سادہ نمبر، جیسے `1234.5`، فیلڈ کا ڈسپلے فارمیٹ کچھ بھی ہو۔ Excel میں یہ اصلی نمبر ہوتا ہے۔ |
| فارمولا | سرور کا نکالا ہوا نمبر، نمبر فیلڈ کی طرح۔ |
| تاریخ منتخب کنندہ اور دستخط کی تاریخ | `YYYY-MM-DD`۔ |
| چیک باکس | `true` یا `false`۔ Excel میں اصلی TRUE یا FALSE۔ |
| ڈراپ ڈاؤن اور ریڈیو گروپ | چنا ہوا اختیار۔ ریڈیو گروپ ایک کالم ہوتا ہے، جو گروپ کے لیبل کے نام پر ہو۔ |
| متعدد انتخاب | چنے ہوئے اختیارات، کوما سے الگ (JSON میں فہرست)۔ |
| فون | ملکی کوڈ کے ساتھ نمبر، جیسے `+46701234567`۔ |
| تصویر اور فائل اپ لوڈ | فائل کا نام۔ فائل خود ایکسپورٹ نہیں ہوتی؛ اسے دستاویز سے ڈاؤن لوڈ کریں۔ |
| دستخط | شامل نہیں: فریق کا Signed کالم بتاتا ہے کہ اس نے کب دستخط کیے۔ |

جو فیلڈ ابھی بھرا نہیں گیا وہ خالی ہوتا ہے، اس لیے زیر التوا دستاویزات بھی ایکسپورٹ ہو سکتی ہیں۔ وہ فیلڈ بھی خالی ہوتا ہے جسے فریق کے دستخط کرتے وقت کسی شرط نے چھپا دیا ہو۔

### کالموں کے نام

کالم کا نام فیلڈ کے لیبل پر ہوتا ہے، یا اگر لیبل نہ ہو تو اس کی قسم پر۔ جب فریقین کے فیلڈز کا لیبل ایک ہی ہو، جیسے ہر ایک کا Name فیلڈ، تو فریق شامل کر دیا جاتا ہے: `Name (Party 1)`، `Name (Party 2)`۔ ایک ہی فریق کا دو بار استعمال ہونے والا لیبل نمبر پاتا ہے: `Note`، `Note (2)`۔ ٹیمپلیٹ میں فیلڈز کو واضح، منفرد لیبل دیں اور کالم اسی کے مطابق ہوں گے۔

مختلف ٹیمپلیٹس کی دستاویزات ایکسپورٹ کرنے پر ہر فیلڈ کا لیبل ایک کالم بن جاتا ہے اور جس دستاویز میں وہ فیلڈ نہ ہو اس میں وہ خالی رہتا ہے۔

## حفاظت

- صرف وہ دستاویزات ایکسپورٹ ہوتی ہیں جو آپ دیکھ سکتے ہیں۔ جن لوگوں کو ہر دستاویز تک رسائی نہیں وہ اپنی اور اپنے ساتھ شیئر کی گئی دستاویزات ایکسپورٹ کرتے ہیں۔
- ایکسپورٹ کے لیے `documents.export` اجازت درکار ہے، جو ایڈمنز، مینیجرز، بھیجنے والوں اور آڈیٹرز کے پاس ہے۔ ناظرین شیئر کی گئی دستاویز کی قدریں دستاویز کے صفحے پر دیکھ سکتے ہیں، لیکن ایکسپورٹ نہیں کر سکتے۔ دیکھیں [صارفین اور کردار](users-and-roles.md#permissions)۔
- ذاتی نمبر کبھی ایکسپورٹ نہیں ہوتے، اور اپ لوڈ کی گئی فائلیں صرف نام سے درج ہوتی ہیں۔
- CSV کا جو سیل `=`، `+`، `-` یا `@` سے شروع ہو اس کے آگے `'` لگایا جاتا ہے تاکہ اسپریڈ شیٹ اسے فارمولے کی طرح چلانے کے بجائے متن کے طور پر دکھائے۔ ورنہ کوئی دستخط کنندہ فیلڈ میں `=HYPERLINK(…)` ٹائپ کر کے اسے آپ کے کمپیوٹر پر چلوا سکتا۔ منفی نمبروں کو ہاتھ نہیں لگایا جاتا۔ Excel فائلیں متن کو متن ہی کے طور پر لکھتی ہیں، اس لیے وہاں کچھ بدلنے کی ضرورت نہیں۔
- CSV فائلیں بائٹ آرڈر مارک کے ساتھ UTF-8 ہوتی ہیں، تاکہ Excel å، ü اور 中 کو صحیح دکھائے۔
- ہر ایکسپورٹ [آڈٹ لاگ](audit-log.md) میں `documents.exported` کے طور پر لکھی جاتی ہے، فارمیٹ، فلٹرز اور اس میں شامل دستاویزات کے ساتھ۔

## API سے

ایک دستاویز کی قدریں، ٹائپ کے ساتھ:

```sh
curl https://sign.example.com/api/v1/documents/$ID/values -H "Authorization: Bearer $KEY"
```

```json
{
  "id": "019a2b11-5d0e-7a42-b6f3-1c9e0d7a4f28",
  "title": "Lease, Storgatan 1",
  "status": "completed",
  "parties": [{ "id": "…", "slot": "Party 1", "role": "signer", "name": "Anna Berg", "email": "anna@example.com", "signedAt": "2026-10-29T10:12:00Z", "…": "…" }],
  "fields": [{ "key": "Monthly rent", "label": "Monthly rent", "kind": "number", "partyId": "…", "fieldIds": ["…"], "value": 12500 }],
  "values": { "Monthly rent": 12500, "Pets": "No", "Rooms": ["Kitchen", "Bath"], "Agree to terms": true }
}
```

`values` سب سے تیز راستہ ہے: فیلڈ کی کلیدیں ٹائپ کی ہوئی قدروں سے جڑی ہوئی۔ `fields` میں وہی قدریں فیلڈ IDs، اقسام اور فریقین کے ساتھ ہیں۔ قدریں پڑھنے کے لیے صرف دستاویز تک رسائی درکار ہے، اور دستاویز کھولنے کی طرح اس کا آڈٹ نہیں ہوتا۔

ایک ساتھ کئی دستاویزات:

```sh
curl -X POST https://sign.example.com/api/v1/exports -H "Authorization: Bearer $KEY" \
  -H "content-type: application/json" -d '{"format": "xlsx", "templateId": "…", "status": "completed"}'
```

باڈی `format` (`csv`، `xlsx` یا `json`) اور `ids`، `templateId`، `bulkId`، `status`، `search`، `folderId` اور `archived` (`true` صرف آرکائیو شدہ دستاویزات کے لیے، `false` انہیں چھوڑنے کے لیے، چھوڑنے پر دونوں) میں سے کوئی بھی لیتی ہے۔ جواب میں `name`، `contentType` اور `count` ہوتے ہیں، اور CSV اور Excel کے لیے `contentBase64` یا JSON کے لیے `documents` (ہر ایک اوپر کی طرح)۔

DocuSign کلائنٹس وہی قدریں `GET /envelopes/{id}/form_data` سے لیتے ہیں؛ دیکھیں [DocuSign API](docusign.md)۔

دونوں کالز MCP ٹولز بھی ہیں، `documents_values` اور `documents_export`، اس لیے ایجنٹ جواب دے سکتا ہے "اس مہینے کتنے کرایہ داروں نے پالتو جانوروں کے لیے ہاں کہا؟" دیکھیں [MCP](mcp.md)۔

## ویب ہُکس کے ساتھ

`document.completed` واقعہ ایک `valuesUrl` لاتا ہے، یعنی اوپر والا `/values` پتہ، تاکہ انٹیگریشن دستخط کنندگان کا درج کردہ سب کچھ ایک کال میں لا سکے۔ ویب ہُکس خود فیلڈ کی قدریں کبھی نہیں لاتے۔ دیکھیں [ویب ہُکس](webhooks.md#events)۔
