# پہلی بار کی ترتیب اور ای میل

نیا انسٹال کسی کے استعمال سے پہلے آپ کو دو مرحلوں سے گزارتا ہے: پہلا ایڈمن بنائیں، پھر ای میل جوڑیں۔ جب تک دونوں مکمل نہ ہوں، OpenSign ہر ایڈمن کو واپس ترتیب کے صفحے پر بھیج دیتا ہے۔

## مرحلہ 1: پہلا ایڈمن

جب OpenSign شروع ہوتا ہے اور کوئی صارف نہیں ہوتا تو وہ اپنے لاگ میں ایک بار استعمال ہونے والا **ترتیبی کوڈ** چھاپتا ہے:

```
No admin yet. Open https://sign.example.com and enter the setup code …
```

انسٹال کو براؤزر میں کھولیں اور یہ بھریں:

| فیلڈ | |
| --- | --- |
| ترتیبی کوڈ | لاگ میں موجود کوڈ۔ یہ ثابت کرتا ہے کہ آپ کو سرور تک رسائی ہے، تاکہ انٹرنیٹ پر نیا انسٹال دیکھنے والا کوئی بھی اسے اپنے نام نہ کر سکے۔ |
| تنظیم | آپ کی تنظیم کا نام۔ دستخط کنندگان اسے ای میلز اور دستخطی صفحے پر دیکھتے ہیں۔ آپ اسے بعد میں **ترتیبات ← تنظیم** میں بدل سکتے ہیں۔ |
| آپ کا نام، ای میل، پاس ورڈ | آپ کا ایڈمن اکاؤنٹ۔ |

**Deploy to Sliplane** بٹن سے ہونے والے انسٹال کوڈ کا مرحلہ چھوڑ دیتے ہیں: ڈیپلائر ایک `SETUP_CODE` بناتا ہے، اور اس کے اختتامی صفحے پر **OpenSign کھولیں** آپ کو `/setup#code=…` پر لے جاتا ہے، جو اسے خود بھر دیتا ہے۔ کوڈ URL کے فریگمنٹ میں ہوتا ہے، جسے براؤزر کبھی سرور کو نہیں بھیجتا، اور صفحہ اسے ایڈریس بار سے ہٹا دیتا ہے۔ اگر آپ انسٹال کو کسی اور طریقے سے کھولیں تو کوڈ ڈیپلائر کے اختتامی صفحے پر اور Sliplane میں سروس کے ماحول میں دکھایا جاتا ہے۔ `SETUP_CODE` مقرر ہو تو لاگ میں کوڈ نہیں چھپتا۔

پہلا ایڈمن بن جانے کے بعد ترتیبی کوڈ ہمیشہ کے لیے کام کرنا چھوڑ دیتا ہے۔ باقی سب کو **ترتیبات ← صارفین** سے مدعو کیا جاتا ہے (دیکھیں [صارفین اور کردار](users-and-roles.md))۔

## مرحلہ 2: ای میل

OpenSign دستخط کے دعوت نامے، یاد دہانیاں، دستاویز رکنے کی اطلاعات، مہر شدہ دستاویزات، صارفین کے دعوت نامے اور پاس ورڈ ری سیٹ ای میل سے بھیجتا ہے۔ ترتیب ایک کام کرنے والا ای میل فراہم کنندہ مانگتی ہے، Resend یا آپ کا اپنا SMTP سرور، اور آپ کو ایک آزمائشی پیغام بھیجتی ہے۔ ترتیب صرف تب مکمل ہوتی ہے جب فراہم کنندہ اسے قبول کر لے، اور اس سے پہلے دستاویزات ای میل سے نہیں جا سکتیں۔

### Resend

[Resend](https://resend.com) ڈیفالٹ فراہم کنندہ ہے۔

1. Resend اکاؤنٹ بنائیں اور **Domains** کے تحت وہ ڈومین تصدیق کریں جس سے آپ بھیجنا چاہتے ہیں۔
2. **API Keys** کے تحت بھیجنے کی اجازت کے ساتھ ایک API کلید بنائیں۔
3. OpenSign میں API کلید، تصدیق شدہ ڈومین پر ایک **بھیجنے والے کا پتہ** (جیسے `sign@example.com`) اور **بھیجنے والے کا نام** درج کریں۔

### SMTP

اپنے میل سرور یا کسی دوسرے فراہم کنندہ کے SMTP ریلے سے بھیجنے کے لیے ترتیب کے دوران **SMTP سرور** ٹیب منتخب کریں، یا **ترتیبات ← ای میل** میں **فراہم کنندہ** کے طور پر **SMTP** منتخب کریں۔

| فیلڈ | |
| --- | --- |
| SMTP سرور | ہوسٹ کا نام، جیسے `smtp.example.com`۔ `smtp://` نہیں اور پورٹ نہیں۔ |
| پورٹ | عام طور پر STARTTLS کے لیے 587 یا TLS کے لیے 465۔ |
| سکیورٹی | **STARTTLS** یا **TLS**۔ |
| صارف نام، پاس ورڈ | خالی صارف نام سائن ان کے بغیر بھیجتا ہے۔ پاس ورڈ خفیہ شکل میں محفوظ ہوتا ہے۔ |
| بھیجنے والے کا پتہ، بھیجنے والے کا نام | بھیجنے والا۔ |

TLS ہمیشہ لازمی ہے اور سرٹیفکیٹ سرور کے نام کے لیے درست ہونا چاہیے، اس لیے اسناد کبھی بغیر انکرپشن کے نہیں جاتیں۔ سادہ متن کا کوئی اختیار نہیں ہے۔ نجی نیٹ ورکس پر موجود سرورز مسترد کر دیے جاتے ہیں، سوائے ڈیولپمنٹ کے۔

### بعد میں ای میل بدلنا

ای میل کی ترتیبات **ترتیبات ← ای میل** میں ہیں۔ فراہم کنندہ، کلید، SMTP سرور یا بھیجنے والا بدلنے سے "تصدیق شدہ" حالت ختم ہو جاتی ہے، اور دستاویزات دوبارہ جانے سے پہلے OpenSign نئی آزمائشی ای میل مانگتا ہے۔ **جواب کا پتہ** اختیاری ہے: خالی ہو تو جوابات ہر دستاویز کے بھیجنے والے کو جاتے ہیں۔

## آگے کیا ترتیب دیں

باقی تمام ترتیب براؤزر میں **ترتیبات** کے تحت ہوتی ہے۔ ای میل لنکس سے دستاویزات بھیجنا شروع کرنے کے لیے اس میں سے کچھ بھی ضروری نہیں۔

- **تنظیم**: نام، رجسٹریشن نمبر، ملک، ٹائم زون، دستخط کنندگان کی ڈیفالٹ زبان، برانڈ کا رنگ اور لوگو۔ دیکھیں [ایڈمن ترتیبات](settings.md)۔
- **SMS**: SMS دعوت ناموں اور یک بار کوڈز کے لیے۔ دیکھیں [شناخت](identification.md#sms-codes)۔
- **BankID اور eID**: سویڈش BankID، Freja eID اور دیگر نارڈک eIDs۔ دیکھیں [شناخت](identification.md)۔
- **دستخط اور مہر**: مہر کا نام، وجہ اور ٹائم اسٹیمپ اتھارٹی۔ دیکھیں [مہر شدہ PDFs اور ثبوت](sealed-pdfs.md)۔
- **سکیورٹی**: سب کے لیے دو مرحلہ سائن ان لازمی کریں۔ دیکھیں [سائن ان، پاس کیز اور دو مرحلہ تصدیق](account-security.md)۔
- **AI**: اختیاری۔ دیکھیں [AI اسسٹنٹ اور جائزہ](ai.md)۔

## ماحولیاتی متغیرات سے ترتیبات مقرر کرنا

کوئی بھی ایڈمن ترتیب `OPENSIGN_<GROUP>_<FIELD>` نام کے ماحولیاتی متغیر سے مقرر کی جا سکتی ہے، مثلاً `OPENSIGN_EMAIL_API_KEY` یا `OPENSIGN_SECURITY_ENFORCE_TWO_FACTOR=true`۔ مقرر کردہ فیلڈ براؤزر میں مقفل ہوتا ہے اور "ماحولیاتی متغیر سے مقرر۔" دکھاتا ہے۔ یہ انفراسٹرکچر بطور کوڈ کے لیے اور کسی سیکرٹ کو ڈیٹا بیس سے بالکل باہر رکھنے کے لیے کارآمد ہے۔ ناموں کی مکمل فہرست کے لیے [ایڈمن ترتیبات](settings.md#pinning-settings) دیکھیں۔
