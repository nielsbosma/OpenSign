# OpenSign دستاویزات

OpenSign ایک اوپن سورس الیکٹرانک دستخطی سروس ہے جسے آپ خود چلاتے ہیں۔ آپ Word یا PDF دستاویز اپ لوڈ کرتے ہیں، فیلڈز رکھتے ہیں اور اسے بھیج دیتے ہیں۔ ہر دستخط کنندہ کو ایک لنک ملتا ہے، وہ آپ کے منتخب کردہ طریقے سے اپنی شناخت ثابت کرتا ہے اور دستخط کرتا ہے۔ سب کے دستخط ہو جانے پر آپ کو ایک مہر شدہ PDF ملتی ہے جس کی تصدیق کوئی بھی PDF ریڈر کر سکتا ہے، اور اس کے ساتھ ثبوت کے صفحات ہوتے ہیں جن میں درج ہوتا ہے کہ کس نے، کب اور کس طریقے سے شناخت کر کے دستخط کیے۔

یہ دستاویزات آپ کی زبان کے مطابق دکھائی جاتی ہیں، اور اوپر زبان کا مینو اسے بدلتا ہے۔ تراجم مشینی ہیں اور انگریزی ورژن ہی مستند ہے۔

یہ صفحات OpenSign کے ہر حصے کا احاطہ کرتے ہیں، ان لوگوں کے لیے جو دستاویزات بھیجتے ہیں، ان ایڈمنز کے لیے جو انسٹال چلاتے ہیں، اور ان ڈویلپرز کے لیے جو اسے دوسرے نظاموں سے جوڑتے ہیں۔

## OpenSign کیا کرتا ہے

- **دستخط کے طریقے۔** دستخط کنندگان، منظوری دینے والے اور دیکھنے والے، مقررہ ترتیب میں یا سب ایک ساتھ۔ لنک ای میل یا SMS سے جاتے ہیں، آپ خود حوالے کرتے ہیں، یا دستخط کنندہ آپ کے آلے پر بالمشافہ دستخط کرتا ہے۔ یاد دہانیاں، میعاد کی تاریخیں اور وجہ بتا کر مسترد کرنا پہلے سے شامل ہیں۔ دیکھیں [فریقین، کردار اور دستخطی ترتیب](parties.md)۔
- **شناخت۔** ای میل لنک، SMS کوڈ، سویڈش BankID (آپ کے اپنے بینک معاہدے کے ساتھ یا TIC Identity کے ذریعے)، Freja eID، یا OpenID Connect بروکر کے ذریعے دیگر نارڈک eIDs۔ فریق پر ذاتی نمبر درج ہو تو صرف وہی شخص دستخط کر سکتا ہے۔ دیکھیں [شناخت](identification.md)۔
- **ٹیمپلیٹس اور بلک بھیجیں۔** تیار دستاویز کو ٹیمپلیٹ کے طور پر محفوظ کریں، پھر اسے CSV یا Excel فائل کی ہر قطار کو بھیجیں۔ دیکھیں [ٹیمپلیٹس](templates.md) اور [بلک بھیجیں](bulk-send.md)۔
- **دستخط کنندہ کے منسلکات۔** کسی فریق سے فائلیں مانگیں، جیسے شناختی دستاویز کی کاپی، جنہیں صاف کر کے دستخط شدہ PDF میں مہر بند کیا جاتا ہے۔ دیکھیں [دستخط کنندہ کے منسلکات](attachments.md)۔
- **مہر شدہ PDFs۔** PAdES B-LTA مہریں، RFC 3161 ٹائم اسٹیمپ کے ساتھ اور وہ سب کچھ جو فائل کو برسوں تک آف لائن جانچنے کے لیے درکار ہے۔ دیکھیں [مہر شدہ PDFs اور ثبوت](sealed-pdfs.md)۔
- **فولڈرز اور آرکائیو۔** دستاویزات اور ٹیمپلیٹس کو مشترکہ فولڈرز میں ترتیب دیں، اور مکمل کام آرکائیو کریں تاکہ فہرستیں مختصر رہیں۔ دیکھیں [فولڈرز اور آرکائیو](folders.md)۔
- **برقراری اور قانونی روک۔** مقررہ مدت کے بعد دستاویزات خود بخود حذف کریں، اور اہم دستاویزات کو قانونی روک سے محفوظ رکھیں۔ دیکھیں [برقراری اور قانونی روک](retention.md)۔
- **صارفین اور کردار۔** ایڈمن، مینیجر، بھیجنے والا، آڈیٹر اور ناظر، دو مرحلہ سائن ان کے لیے پاس کیز یا تصدیقی ایپ کے ساتھ۔ دیکھیں [صارفین اور کردار](users-and-roles.md)۔
- **APIs۔** OpenAPI کے ساتھ REST API، براہ راست مطابقت رکھنے والے Scrive اور DocuSign اینڈ پوائنٹس، دستخط شدہ ویب ہُکس، اور Claude اور دیگر AI کلائنٹس کے لیے MCP سرور۔ دیکھیں [REST API](api.md)۔
- **AI، اگر آپ چاہیں۔** ایک اسسٹنٹ اور بھیجنے سے پہلے دستاویزات کا جائزہ۔ جب تک ایڈمن کوئی فراہم کنندہ منتخب نہ کرے یہ بند رہتا ہے۔ دیکھیں [AI اسسٹنٹ اور جائزہ](ai.md)۔
- **سکیورٹی سب سے پہلے۔** ذخیرہ شدہ ڈیٹا کی انکرپشن، چھیڑ چھاڑ ظاہر کرنے والی آڈٹ ٹریل، سخت ویب سکیورٹی ہیڈرز، اور ہر کال پر سرور کی سطح پر اجازتوں کی جانچ۔ دیکھیں [سکیورٹی ماڈل](security.md)۔

## یہ سب کیسے جڑا ہے

OpenSign ایک کنٹینر امیج ہے۔ اسے Postgres، ایک S3 سے ہم آہنگ بکٹ، اور اگر آپ Word فائلیں قبول کرنا چاہتے ہیں تو نجی نیٹ ورک پر Gotenberg کنورٹر درکار ہے۔ ویب ایپ، APIs، MCP سرور اور پس منظر کا ورکر سب ایک ہی امیج میں چلتے ہیں اور ایک ہی سروسز استعمال کرتے ہیں، اس لیے درخواست جیسے بھی آئے، اجازت یا قاعدہ ایک ہی طرح لاگو ہوتا ہے۔

```
           ┌──────────────── one container ───────────────────────────┐
 browser ─▶│ React app ─ RPC ──┐                                      │
 REST/API ▶│ REST, Scrive,     ├─▶ services (permissions, audit, ──▶ Postgres
 Claude  ─▶│ DocuSign, MCP ────┤   settings, encryption)          ──▶ S3 (encrypted files)
 signer  ─▶│ signing page ─────┘   worker: email, SMS, sealing,   ──▶ Email, SMS, eID, TSA, LLM
           │                       webhooks, reminders            ──▶ Gotenberg (private)
           └──────────────────────────────────────────────────────────┘
```
