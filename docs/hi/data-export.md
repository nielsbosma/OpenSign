# भरा हुआ डेटा निर्यात करना

हस्ताक्षरकर्ता फ़ील्ड में जो टाइप करते हैं वह मुहरबंद PDF में पहुँचता है, और आप उसे डेटा के रूप में भी निकाल सकते हैं: स्प्रेडशीट के रूप में, JSON के रूप में, API से, या MCP के ज़रिए किसी AI एजेंट से।

## ऐप से

**डेटा निर्यात करें** चुनें, फिर **Excel**, **CSV** या **JSON**:

- **दस्तावेज़** पृष्ठ पर, **नया दस्तावेज़** के बगल में। निर्यात में वे दस्तावेज़ होते हैं जो सूची दिखाती है: आपके चुने स्थिति टैब, फ़ोल्डर, खोज और संग्रह टैब के अनुसार, केवल वह पृष्ठ नहीं जो आप देख रहे हैं।
- **दस्तावेज़** पृष्ठ पर पंक्तियाँ चुनकर, **कार्रवाइयाँ** के अंतर्गत, केवल उन दस्तावेज़ों के लिए।
- किसी टेम्पलेट पर, **⋯** मेनू में, उससे बने हर दस्तावेज़ के लिए।
- किसी बल्क भेजने पर, उसके बनाए हर दस्तावेज़ के लिए।
- किसी दस्तावेज़ पर, **⋯** मेनू में, उसी एक दस्तावेज़ के लिए।

एक निर्यात में अधिकतम 5,000 दस्तावेज़ होते हैं। ज़्यादा निर्यात करने के लिए फ़िल्टर संकरे करके हिस्सों में निर्यात करें।

## इसमें क्या होता है

स्प्रेडशीट में हर दस्तावेज़ की एक पंक्ति होती है, सबसे पुराना पहले:

| कॉलम | |
| --- | --- |
| Document ID, Title, Reference, Status | दस्तावेज़। Reference वही है जो आपने **आपका संदर्भ** में भरा। |
| Created, Sent, Completed | UTC में समय। |
| Party 1 Name, Party 1 Email, Party 1 Signed | हर पक्ष हस्ताक्षर क्रम में, फिर Party 2 और इसी तरह। |
| हर फ़ील्ड के लिए एक कॉलम | फ़ील्ड के लेबल के नाम पर। |

फ़ील्ड मान उसी तरह लिखे जाते हैं जैसे OpenSign उन्हें सहेजता है, ताकि वे स्प्रेडशीट में छाँटे और जोड़े जा सकें:

| फ़ील्ड | मान |
| --- | --- |
| संख्या | सादी संख्या, जैसे `1234.5`, फ़ील्ड का डिस्प्ले प्रारूप चाहे जो हो। Excel में यह असली संख्या होती है। |
| फ़ॉर्मूला | सर्वर की निकाली संख्या, संख्या फ़ील्ड की तरह। |
| तारीख चयनकर्ता और हस्ताक्षर की तारीख | `YYYY-MM-DD`। |
| चेकबॉक्स | `true` या `false`। Excel में असली TRUE या FALSE। |
| ड्रॉपडाउन और रेडियो समूह | चुना हुआ विकल्प। रेडियो समूह एक कॉलम होता है, जो समूह के लेबल के नाम पर होता है। |
| बहुविकल्पी | चुने हुए विकल्प, अल्पविराम से अलग (JSON में एक सूची)। |
| फ़ोन | देश कोड सहित नंबर, जैसे `+46701234567`। |
| छवि और फ़ाइल अपलोड | फ़ाइल का नाम। फ़ाइल खुद निर्यात नहीं होती; उसे दस्तावेज़ से डाउनलोड करें। |
| हस्ताक्षर | छोड़ा जाता है: पक्ष का Signed कॉलम बताता है कि उसने कब हस्ताक्षर किए। |

जो फ़ील्ड अभी भरा नहीं गया वह खाली होता है, इसलिए लंबित दस्तावेज़ भी निर्यात किए जा सकते हैं। वह फ़ील्ड भी खाली होता है जिसे पक्ष के हस्ताक्षर करते समय किसी शर्त ने छिपा दिया था।

### कॉलम के नाम

कॉलम का नाम फ़ील्ड के लेबल पर होता है, या लेबल न हो तो उसके प्रकार पर। जब पक्षों के फ़ील्ड का लेबल एक ही हो, जैसे हर एक का Name फ़ील्ड, तो पक्ष जोड़ दिया जाता है: `Name (Party 1)`, `Name (Party 2)`। एक ही पक्ष का दो बार इस्तेमाल हुआ लेबल संख्या पाता है: `Note`, `Note (2)`। टेम्पलेट में फ़ील्ड को स्पष्ट, अनन्य लेबल दें और कॉलम उनके अनुसार बनेंगे।

जब आप अलग-अलग टेम्पलेट के दस्तावेज़ निर्यात करते हैं, तो हर फ़ील्ड लेबल एक कॉलम बन जाता है और वह फ़ील्ड न रखने वाला दस्तावेज़ उसे खाली छोड़ देता है।

## सुरक्षा

- केवल वही दस्तावेज़ निर्यात होते हैं जिन्हें आप देख सकते हैं। जिनके पास सभी दस्तावेज़ों की पहुँच नहीं है, वे अपने और अपने साथ साझा किए गए दस्तावेज़ निर्यात करते हैं।
- निर्यात के लिए `documents.export` अनुमति चाहिए, जो एडमिन, मैनेजर, भेजने वालों और ऑडिटर के पास होती है। दर्शक किसी साझा दस्तावेज़ के मान दस्तावेज़ पृष्ठ पर देख सकते हैं, पर निर्यात नहीं कर सकते। देखें [उपयोगकर्ता और भूमिकाएँ](users-and-roles.md#permissions)।
- व्यक्तिगत संख्याएँ कभी निर्यात नहीं होतीं, और अपलोड की गई फ़ाइलें केवल नाम से सूचीबद्ध होती हैं।
- जो CSV सेल `=`, `+`, `-` या `@` से शुरू होता है उसके आगे `'` लगा दिया जाता है, ताकि स्प्रेडशीट उसे फ़ॉर्मूले की तरह चलाने के बजाय टेक्स्ट के रूप में दिखाए। नहीं तो कोई हस्ताक्षरकर्ता फ़ील्ड में `=HYPERLINK(…)` टाइप करके उसे आपके कंप्यूटर पर चलवा सकता है। ऋणात्मक संख्याओं को छुआ नहीं जाता। Excel फ़ाइलें टेक्स्ट को टेक्स्ट के रूप में लिखती हैं, इसलिए वहाँ कुछ बदलने की ज़रूरत नहीं।
- CSV फ़ाइलें बाइट ऑर्डर मार्क के साथ UTF-8 होती हैं, ताकि Excel å, ü और 中 को सही दिखाए।
- हर निर्यात [ऑडिट लॉग](audit-log.md) में `documents.exported` के रूप में लिखा जाता है, प्रारूप, फ़िल्टर और उसमें शामिल दस्तावेज़ों के साथ।

## API से

एक दस्तावेज़ के मान, टाइप किए हुए:

```sh
curl https://sign.example.com/api/v1/documents/$ID/values -H "Authorization: Bearer $KEY"
```

```json
{
  "id": "019a2b11-5d0e-7a42-b6f3-1c9e0d7a4f28",
  "title": "Lease, Storgatan 1",
  "status": "completed",
  "parties": [{ "id": "…", "slot": "Party 1", "role": "signer", "name": "Anna Berg", "email": "anna@example.com", "signedAt": "2026-10-29T10:12:00Z", "…": "…" }],
  "fields": [{ "key": "Monthly rent", "label": "Monthly rent", "kind": "number", "partyId": "…", "fieldIds": ["…"], "value": 12500 }],
  "values": { "Monthly rent": 12500, "Pets": "No", "Rooms": ["Kitchen", "Bath"], "Agree to terms": true }
}
```

`values` सबसे तेज़ रास्ता है: फ़ील्ड कुंजियाँ टाइप किए हुए मानों से मैप की हुई। `fields` में वही मान उनकी फ़ील्ड ID, प्रकार और पक्षों के साथ होते हैं। मान पढ़ने के लिए केवल दस्तावेज़ तक पहुँच चाहिए, और दस्तावेज़ खोलने की तरह इसका ऑडिट नहीं होता।

एक साथ कई दस्तावेज़:

```sh
curl -X POST https://sign.example.com/api/v1/exports -H "Authorization: Bearer $KEY" \
  -H "content-type: application/json" -d '{"format": "xlsx", "templateId": "…", "status": "completed"}'
```

बॉडी में `format` (`csv`, `xlsx` या `json`) और `ids`, `templateId`, `bulkId`, `status`, `search`, `folderId` और `archived` (केवल संग्रहीत दस्तावेज़ों के लिए `true`, उन्हें छोड़ने के लिए `false`, दोनों के लिए न देना) में से कोई भी दिया जा सकता है। उत्तर में `name`, `contentType` और `count` होते हैं, साथ में CSV और Excel के लिए `contentBase64` या JSON के लिए `documents` (हर एक ऊपर जैसा)।

DocuSign क्लाइंट को वही मान `GET /envelopes/{id}/form_data` से मिलते हैं; देखें [DocuSign API](docusign.md)।

दोनों कॉल MCP टूल भी हैं, `documents_values` और `documents_export`, ताकि कोई एजेंट "इस महीने कितने किराएदारों ने पालतू जानवरों के लिए हाँ कहा?" का उत्तर दे सके। देखें [MCP](mcp.md)।

## वेबहुक के साथ

`document.completed` इवेंट एक `valuesUrl` रखता है, यानी ऊपर वाला `/values` पता, ताकि कोई इंटीग्रेशन हस्ताक्षरकर्ताओं की दर्ज की हर चीज़ एक कॉल में ले सके। वेबहुक खुद कभी फ़ील्ड मान नहीं ले जाते। देखें [वेबहुक](webhooks.md#events)।
