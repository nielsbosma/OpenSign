# 首次运行设置与邮件

全新安装需要先完成两个步骤才能使用：创建第一个管理员，然后连接邮件。在两者都完成之前，OpenSign 会把每位管理员都带回设置页面。

## 步骤 1：第一个管理员

OpenSign 启动时如果还没有任何用户，会在日志中打印一次性的**设置密钥**：

```
No admin yet. Open https://sign.example.com and enter the setup code …
```

在浏览器中打开该实例，并填写：

| 字段 | |
| --- | --- |
| 设置密钥 | 日志中的密钥。它证明你能访问服务器，因此在互联网上发现全新实例的人无法抢先认领。 |
| 组织 | 你的组织名称。签署人会在邮件和签署页面上看到它。之后可以在**设置 → 组织**中修改。 |
| 你的姓名、邮箱、密码 | 你的管理员账户。 |

通过 **Deploy to Sliplane** 按钮安装的实例可以跳过密钥：部署程序会生成一个 `SETUP_CODE`，其完成页面上的**打开 OpenSign**会跳转到 `/setup#code=…`，自动填入密钥。密钥位于 URL 片段中，浏览器永远不会把它发送给服务器，页面还会把它从地址栏中移除。如果你用其他方式打开该实例，密钥会显示在部署程序的完成页面上，也可以在 Sliplane 中该服务的环境变量里找到。设置了 `SETUP_CODE` 之后，日志不再打印密钥。

第一个管理员创建后，设置密钥就永久失效。其他人都在**设置 → 用户**中邀请（参见 [用户与角色](users-and-roles.md)）。

## 步骤 2：邮件

OpenSign 通过邮件发送签署邀请、提醒、文档被停止的通知、封印后的文档、用户邀请和密码重置。设置过程会要求你配置一个可用的邮件提供商，Resend 或你自己的 SMTP 服务器，并给你发一封测试邮件。只有提供商接受测试邮件后设置才会完成，在此之前文档无法通过邮件发出。

### Resend

[Resend](https://resend.com) 是默认的提供商。

1. 创建 Resend 账户，并在**域名**下验证你要用来发信的域名。
2. 在 **API 密钥**下创建一个具有发送权限的 API 密钥。
3. 在 OpenSign 中输入 API 密钥、验证过的域名下的**发件地址**（例如 `sign@example.com`）和**发件人名称**。

### SMTP

在设置过程中选择 **SMTP 服务器**标签页，或在**设置 → 邮箱**中把**提供商**设为 **SMTP**，即可通过你自己的邮件服务器或其他服务商的 SMTP 中继发信。

| 字段 | |
| --- | --- |
| SMTP 服务器 | 主机名，例如 `smtp.example.com`。不要带 `smtp://`，也不要带端口。 |
| 端口 | STARTTLS 通常为 587，TLS 通常为 465。 |
| 安全 | **STARTTLS** 或 **TLS**。 |
| 用户名、密码 | 用户名为空表示不登录直接发送。密码以加密方式存储。 |
| 发件地址、发件人名称 | 发件人。 |

始终要求使用 TLS，且证书必须对该服务器名称有效，因此凭据不会以明文传输。没有明文选项。位于私有网络中的服务器会被拒绝，开发环境除外。

### 之后更改邮件设置

邮件设置位于**设置 → 邮箱**。更改提供商、密钥、SMTP 服务器或发件人会清除“已验证”状态，OpenSign 会要求重新发送一封测试邮件，之后文档才能再次发出。**回复地址**是可选的：留空时，回复会发给发送每份文档的人。

## 接下来要设置什么

所有其他配置都在浏览器中的**设置**下完成。要开始通过邮件链接发送文档，这些都不是必需的。

- **组织**：名称、注册号、国家/地区、时区、默认签署人语言、品牌颜色和徽标。参见 [管理员设置](settings.md)。
- **短信**：用于短信邀请和一次性验证码。参见 [身份验证](identification.md#sms-codes)。
- **BankID 与电子身份**：瑞典 BankID、Freja eID 和其他北欧电子身份。参见 [身份验证](identification.md)。
- **签署与印章**：印章名称、原因和时间戳机构。参见 [封印 PDF 与证据](sealed-pdfs.md)。
- **安全**：要求所有人使用双重验证登录。参见 [登录、通行密钥与双重验证](account-security.md)。
- **AI**：可选。参见 [AI 助手与审阅](ai.md)。

## 用环境变量固定设置

任何管理员设置都可以用名为 `OPENSIGN_<GROUP>_<FIELD>` 的环境变量来设定，例如 `OPENSIGN_EMAIL_API_KEY` 或 `OPENSIGN_SECURITY_ENFORCE_TWO_FACTOR=true`。被固定的字段在浏览器中会被锁定，并显示“由环境变量设置。”。这对基础设施即代码很方便，也能让密钥完全不进入数据库。完整的名称列表参见 [管理员设置](settings.md#pinning-settings)。
