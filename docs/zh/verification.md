# 验证文档

任何持有已签署 PDF 的人都可以检查它是否真实且未被更改。不需要账户。

## 在验证页面上

打开 `https://<your-install>/verify`（在应用侧边栏中也链接为**验证文档**，并印在每份封印文档的证据页上），然后拖入 PDF。

文件在服务器上检查，不会被存储。页面回答两个问题：

1. **这个实例是否封印了这份确切的文件？**“由本 OpenSign 封印”并显示文档标题和完成时间，表示该文件的 SHA-256 与本服务器封印的某份文档相符，并且其印章成立，是用本服务器的某张印章证书制作的。“不是本服务器封印的文档”表示它在封印后被更改过，或者来自其他地方。
2. **签名是否完好？**文件中的每个签名和时间戳都会列出，说明由谁制作、何时制作，以及是否完好。完好仅表示字节与签署时一致：任何人都可以制作一张写着任意名称的证书。完好但不是由本服务器制作的签名会注明这一点，其上的名称未经确认。

## 检查涵盖什么

对于文件中的每个签名和文档时间戳，OpenSign 会检查：

- 签名的密码学是否有效，并覆盖它所声称的字节，
- 它是覆盖整个文件，还是只覆盖较早的修订版本，
- 它之后添加的内容是否只是验证数据：含有证书和吊销应答的文档安全存储，以及不可见的文档时间戳，
- 时间戳机构自己的签名（2048 位或更长的 RSA、ECDSA P-256 和 P-384、SHA-2）、其证书是否用于时间戳，以及在被盖章的时刻是否有效。未通过这些检查的时间戳不显示时间。

签名之后的任何其他更改，例如新的批注、表单编辑、被改动的目录条目、被删除的对象，或似乎无人使用的新对象，都会使该签名被标记为不完好。如果更新的写法与 OpenSign 自己的朴素写法不同，也是如此。这堵住了用某些阅读器不会标记的增量更新来改动已签署 PDF 的常见手法，同时也意味着，被其他工具添加了验证数据的文件可能显示为已更改。

OpenSign 不会根据信任列表检查签署者或时间戳机构。为此，请使用带有信任列表的 PDF 阅读器。

## 在 PDF 阅读器中

封印后的文档是标准的 PAdES 文件，因此 Adobe Acrobat、Foxit 和其他能识别签名的阅读器会显示印章、时间戳以及文档是否被更改。由于印章证书默认是自签名的，阅读器可能会说它不知道签署者的身份；上面的验证页面才是针对你的实例的权威检查。参见 [封印 PDF 与证据](sealed-pdfs.md#the-seal-certificate)。

## 通过 API

`POST /api/v1/verify`，以原始 PDF 作为请求体（最大 40 MB），会以 JSON 形式返回相同的结果。它不需要 API 密钥，并按地址限速。参见 [REST API](api.md)。

```sh
curl -X POST https://sign.example.com/api/v1/verify \
  -H "Content-Type: application/pdf" --data-binary @signed.pdf
```
