# 报告问题

发现有什么不能用？直接在 OpenSign 里报告。你的报告会以你自己的名义成为 GitHub 上的一个公开 issue，让开发 OpenSign 的人看到你看到的情况。

## 如何报告

1. 打开侧边栏底部你名字下方的菜单，选择 **报告问题**。
2. 页面底部会打开一个面板。选择一个工具：
   - **评论**：点击一个元素，说明它哪里有问题，然后按 Enter。它会得到一个带编号的框。
   - **隐藏**：在任何隐私内容上拖动，将其涂黑。
   - **暂停**：照常使用页面，例如先打开一个菜单或对话框。按 Esc 也会暂停。
3. 描述出了什么问题，以及你原本期望的结果。标题可以不填。
4. 按 **审阅报告**。你会看到最终的截图和将要发送的每一行。修改或删除任何你不想分享的内容，也可以不附截图。
5. 勾选确认报告可以公开的复选框，然后按 **在 GitHub 上继续**。
6. 错误报告服务会打开一个新窗口，再显示一次报告。在那里用 GitHub 登录并发布。之后窗口会链接到你的新 issue。

你需要一个注册至少一周的 GitHub 账户。如果浏览器拦截了新窗口，OpenSign 会显示一个链接，让你自己打开。

## 会公开哪些内容

issue 中显示：

- 你的标题和描述，以及你的评论和每条评论针对的元素，
- 截图（如果你保留了），
- 以模式表示的页面，例如 `/documents/:id`，OpenSign 版本，你的浏览器和系统，窗口大小和应用语言，
- 已打开对话框的标题、最近的控制台错误和最近失败的请求（如果你保留了这些行）。

它绝不会显示你的 OpenSign 地址、真实的页面地址、你在 OpenSign 中的姓名或电子邮件地址，也不会显示文档内容。技术信息行在离开 OpenSign 之前会去掉电子邮件地址、网址、ID、令牌、密钥和长数字，每一项都替换为 `[removed]`。

issue 由你的 GitHub 账户创建，带有 **OpenDeploy Bug Reports** 应用的徽章，该应用只能创建 issue。服务只将你的登录用于这一次请求，随后即撤销。

## 截图中会遮盖哪些内容

截图之前，OpenSign 会用灰色遮盖：

- 字段中输入的所有内容，
- PDF 页面和缩略图，
- 参与方和用户的姓名与电子邮件地址，
- 文档标题，
- 审计日志条目，
- webhook 地址和 API 密钥允许的 IP 地址。

你用 **隐藏** 画的黑框也会烧录进图片。页面本身不会有任何变化。请在审阅步骤中查看截图：其他任何隐私内容需要你自己隐藏。

## 删除截图

截图是公开的，会一直保留到有人删除为止。每个 issue 的末尾都有 **删除此截图**。打开它，用 GitHub 登录，图片就会被删除，issue 中也会注明。你可以删除自己的截图；仓库的维护者可以删除任何截图。

GitHub 会在一段时间内保留图片的缓存副本，任何人也都可能已经保存了它，因此删除截图无法收回每一份副本。这就是为什么审阅步骤要求你确认屏幕上没有隐私内容。

## 哪些内容会离开你的 OpenSign

在你按下 **在 GitHub 上继续** 之前，什么都不会发送。之后，你的 OpenSign 服务器会把报告发送到位于 `sliplane.opendeploy.cloud` 的错误报告服务，该服务最多保留一小时，直到你发布它。OpenSign 不保存任何 GitHub 凭据。

每人每小时可以发送 10 份报告，每个 OpenSign 每小时 30 份。

## 管理员须知

错误报告默认开启。管理员可以在 **设置 → 错误报告** 中将其关闭，这会对所有人隐藏 **报告问题**；也可以把报告发送到另一个仓库，例如一个 fork。参见 [管理员设置](settings.md#bug-reports)。每份发送的报告都会记录在审计日志中。

没有出站互联网访问的安装无法发送报告。
