# 当面签署

当面签署让参与方在你自己的电脑或平板上签署，例如在柜台、会议中，或在客户家里。参与方不需要邮箱地址或手机。

## 设置

在参与方对话框中，把**链接发送方式**设为**当面（在你的设备上）**。这样 OpenSign 不会向该参与方发送任何内容。你仍然可以要求他们用短信验证码或电子身份验证身份；他们在你的设备上完成。

## 签署

1. 照常发送文档。
2. 轮到该参与方时，打开文档，在其参与方卡片上选择**当面签署**。
3. OpenSign 会打开签署页面，并显示一个交接屏幕：“请将设备交给 …”。屏幕上说明他们的所有操作都会记录在文档的证据中。
4. 参与方用**我是 …**确认身份，阅读文档，如有要求则验证身份，然后签署。
5. 完成后，页面会请他们把设备交还给你。

## 会记录什么

- 开始当面签署会为该参与方签发新的链接，并停用此前所有的链接，因此你之前开始时生成的链接无法再使用。
- 审计日志记录是谁为哪位参与方发起了当面签署会话。证据页会显示该参与方的身份验证、IP 地址和浏览器，与其他签署人一样。

## 自己签署文档

对于只有你需要签署的文档，例如声明、订单确认，或你为自己的记录而填写的表单，请在草稿上选择**自己签署**，而不是**发送**。

1. 选择你的验证方式：**我的 OpenSign 登录**（默认），或管理员已设置好的电子身份，例如 BankID。
2. 选择**立即签署**。你会成为唯一的签署人：草稿上已有的签署人和审批人会被移除，他们的字段归你所有。接收副本的人仍会收到副本。
3. OpenSign 发送文档，并在你的设备上打开签署页面，没有交接屏幕。如果你有[已保存的签名](account-security.md#saved-signature)，会提供给你使用。
4. 你签署之后，文档会被封印，并像其他任何文档一样可验证。

使用**我的 OpenSign 登录**时，证据页会写明“Identified by: Signed-in OpenSign account”以及你的姓名和邮箱，审计日志则记录发起它的用户。如果你在签署之前离开，可以在你的参与方卡片上点击**当面签署**，重新打开签署页面。

## 注意事项

- 只有在文档处于等待中、且轮到该参与方时，才会为投递方式为当面的参与方提供**当面签署**。
- 开始当面签署，或自己签署文档，需要已登录的用户。使用 API 密钥或通过 MCP 都无法进行。
- Scrive 的 `pad` 投递对应于当面签署。参见 [Scrive 兼容](scrive.md)。
