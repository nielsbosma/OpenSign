# 封印 PDF 与证据

最后一位参与方签署后，OpenSign 会把文档变成一份封印后的 PDF。它包含盖入了每个值和签名的文档、讲述签署经过的证据页，以及表明文件此后未被更改的数字印章。任何人都可以用普通的 PDF 阅读器或在[验证页面](verification.md)上检查它，并且它可在离线状态下多年保持可验证。

## 封印后的 PDF 包含什么

1. **文档**本身，与发送时完全一致，每位参与方的字段值和签名都盖在原位。
2. 末尾的**证据页**：
   - 你的[徽标](settings.md#logo)（如果上传了），以及文档标题、其 ID 和你的组织，
   - 每位参与方：姓名、邮箱、角色、验证身份的方式（例如“Swedish BankID, personal number 19xxxxxx-1234”）、签署时间及其 IP 地址，
   - 审计日志中的事件：已发送、已打开、已验证身份、已签署等，并带有时间，
   - 签署人上传的附件以及所有[网络摄像头照片](identification.md#webcam-photo)，附带它们的 SHA-256 哈希，
   - 原始 PDF 的 SHA-256 哈希，以及验证文档的地点。
3. **嵌入文件**：一个 JSON 证据附件，以机器可读的形式包含相同的事实，以及[签署人附件](attachments.md)和网络摄像头照片。
4. **印章**：以你组织的名义对整个文件作出的 PAdES 签名，带有 RFC 3161 时间戳。
5. **长期验证数据**和存档时间戳（见下文）。

## PAdES B-LTA

该印章遵循 PAdES Baseline B-LTA，这是欧洲标准中针对必须长期保持可验证的文档的级别：

- **B-B**：由组织印章对整个文件作出的 CAdES 签名。
- **B-T**：来自受信任时间戳机构的 RFC 3161 时间戳，证明印章是何时制作的。
- **B-LT**：印章和时间戳所依赖的每一张证书，以及各自的 OCSP 响应或 CRL，存放在 PDF 的文档安全存储中。即使证书过期后，也无需联系任何人就能验证该文件。
- **B-LTA**：覆盖所有内容（包括验证数据）的文档时间戳。

OpenSign 在存储每个 OCSP 响应或 CRL 之前都会检查它：它必须由颁发者或其委托的响应方签名，针对正确的证书，并且仍然有效。验证数据和存档时间戳以增量更新的方式添加，因此印章所覆盖的字节永远不会改变。

如果无法获取吊销数据，文档仍会被封印，并将该缺口记录在审计日志中。响应方报告为已吊销的证书同样如此。如果多次尝试后仍无法连接时间戳机构，文档会在没有时间戳的情况下封印，而不是一直等待。

## 印章证书

OpenSign 在第一次封印文档时于服务器上生成印章密钥，作为以你组织名义的自签名证书，并加密存储。**设置 → 签署与印章**会显示证书的主体及其有效期。

**替换印章密钥**会以组织当前的名称创建一张新的自签名证书。新文档使用它封印。之前封印的文档仍然有效且可验证。

由于证书是自签名的，PDF 阅读器会显示印章有效且文档未被更改，但在你信任该证书之前，可能会说它们不知道签署者的身份。验证页面会检查你的实例是否封印了这份确切的文件。

## 设置

在**设置 → 签署与印章**中：

| 设置 | |
| --- | --- |
| 印章名称 | 显示为印章的签署者。留空则使用组织名称。 |
| 签名原因 | 记录在印章中的原因。默认：“Signed with OpenSign”。 |
| 时间戳机构（RFC 3161） | 时间戳机构的 URL。默认：`http://timestamp.digicert.com`。 |

## 获取封印后的 PDF

- **发送人**：从文档页面下载，页面上也提供发送时的原件。
- **参与方**：文档完成时，每位有邮箱地址的人都会通过邮件收到它。最大 10 MB 的文件作为附件，更大的则以下载链接发送。在链接有效期间，签署页面也提供**下载已签署的文件**。
- **API**：`GET /api/v1/documents/{id}/file?version=signed`。参见 [REST API](api.md)。
- **Webhook**：`document.completed` 带有封印后文件的 SHA-256。参见 [Webhook](webhooks.md)。

每次下载都会记录在审计日志中。

## 受信任的时间戳机构

任何人都可以运行时间戳机构，所以仅仅检查过时间戳只能说明它的令牌是完好的。要让验证页面说明你信任哪些时间戳，请在管理员设置 → 签署与印章中的**受信任的时间戳机构**下，列出它们证书的 SHA-256 指纹。该列表默认为空。
