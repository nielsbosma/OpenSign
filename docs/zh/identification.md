# 身份验证

你可以为每位参与方选择他们必须以多强的方式证明自己的身份，分别针对打开文档（**查看前验证身份**）和签署文档（**签署前验证身份**）。无论他们使用哪种方式，都会记录在审计日志以及封印后 PDF 的证据页上。

## 方式

| 方式 | 查看时 | 签署时 | 需要 |
| --- | --- | --- | --- |
| **无** | 默认 | | 持有链接即可打开文档。 |
| **标准** | | 默认 | 持有链接。适用于邮件和短信投递，因为只有收件人能拿到链接。 |
| **短信验证码**（`sms_pin`） | 是 | 是 | 短信提供商，以及参与方的手机号码。 |
| **瑞典 BankID**（`se_bankid`） | 是 | 是 | 直接使用 BankID，或通过 TIC Identity。 |
| **Freja eID**（`freja`） | 是 | 是 | Freja eID 协议。 |
| **其他电子身份**（`broker`） | 是 | 是 | OpenID Connect 电子身份代理，例如 Idura（Criipto）或 Signicat。 |

在参与方对话框中，实例上尚未设置的方式会显示为禁用。如果参与方使用的方式尚未就绪，发送会被拒绝，因此签署人不会被卡住。

## 网络摄像头照片

在签署人或审批人上勾选**要求网络摄像头身份验证**。在他们能签署之前，需要用电脑摄像头或手机为自己拍一张实时照片：**打开摄像头**、**拍照**，然后**使用照片**或**重拍**。没有文件选择器。

- 照片会清除 EXIF 和位置数据，加密存储，并连同其 SHA-256 哈希嵌入封印后的 PDF。审计日志会记录拍摄时间。
- 在文档页面上，参与方卡片会显示照片及拍摄时间。每次查看都会记录在审计日志中。
- 只有签署页面可以使用摄像头。OpenSign 中的其他所有页面都会阻止使用。

照片是谁签署的证据，而不是活体证明：有经验的签署人可能会发送静态图像而不是实时画面。如需强身份验证，请使用电子身份。

## 个人身份号码

对于 BankID 和 Freja，请在参与方上填写其**个人身份号码**。这样 OpenSign 会要求电子身份指向的恰好是此人：其他任何人的验证都会被拒绝，并记录在审计日志中。没有个人身份号码时，任何持有链接并拥有电子身份的人都可以签署，设置检查会对此发出警告。

个人身份号码加密存储并以掩码显示（仅显示最后四位），每位参与方收到的封印后 PDF 中也是如此。电子身份返回的完整号码仍以加密形式保存在数据库中。编辑参与方时，将该字段留空即可保留已存储的号码。

## 查看前与签署前验证身份

**查看前验证身份**和**签署前验证身份**是两个独立的步骤，即使使用同一个电子身份也是如此。只有为签署而进行的验证才会告诉用户他们在签署什么（BankID 会在应用中显示），所以两者都设置的参与方需要验证两次。

## 短信验证码

参与方在签署页面请求验证码，并通过短信收到一个 6 位验证码。

- 验证码有效期 10 分钟，允许尝试 5 次。
- 每小时最多可向一位参与方发送 5 个验证码。
- 验证码仅以带密钥的哈希形式存储。
- 封印后的 PDF 中的电话号码只显示最后三位数字。

### 设置短信

在**设置 → 短信**中选择提供商：

| 提供商 | 用户名 | 密码 |
| --- | --- | --- |
| [46elks](https://46elks.com) | API 用户名 | API 密码 |
| [Twilio](https://www.twilio.com) | 账户 SID | 认证令牌 |

**发送人**是最多 11 个字母的名称，或你拥有的号码。签署链接的短信投递使用同一个提供商。

### 限制短信的费用

短信是要花钱的，而共享链接会让你不认识的人也能请求发送短信。以下设置可以让账单保持在可控范围内：

- **允许的国家/地区**：可接收短信的国家电话区号，例如 `46, 47`。留空表示允许所有国家，这是安装时的初始状态，以免已有的功能失效。请把它设置为你实际发送的国家：国外的某些号码的费用是本地号码的许多倍。
- **每小时消息数**（默认 200）和**每天消息数**（1000）：针对该实例发送的所有消息。达到其中一个限制后，在时间窗口过去之前，进一步的消息会被拒绝，服务器会记录一条警告。
- **每个共享链接每小时消息数**（30）：针对由同一个共享链接生成的所有文档。

0 表示不限制。

## 瑞典 BankID

签署人用 BankID 应用验证身份：在同一设备上通过**在此设备上打开 BankID**，或通过**在其他设备上使用 BankID** 扫描二维码。如果参与方有个人身份号码，则只有此人的 BankID 才能应答。

连接 BankID 有两种方式。无论哪种方式，参与方选择的都是“瑞典 BankID”。

### 使用你自己的 BankID 协议

1. 在**设置 → BankID 与电子身份**中，开启**瑞典 BankID**。
2. 要试用，请开启**使用 BankID 测试环境**并让证书留空。OpenSign 会使用 BankID 的公开测试证书，你可以用[测试 BankID](https://developers.bankid.com/test-portal) 进行签署。
3. 用于生产环境时，请关闭测试环境，并上传银行提供给你的依赖方证书（`.p12` 文件）及其密码。

OpenSign 通过双向 TLS 与 BankID 通信，并且只信任 BankID 自己的根证书，该证书已内置。只有在 BankID 通知你时，才需要在 **BankID 服务器 CA** 下替换它。

### 通过 TIC Identity

[TIC Identity](https://id.tic.io) 让你无需与银行签订自己的协议即可使用 BankID。

1. 在 TIC 的门户中，为你的租户开启 OpenID Connect，并把 `https://<your-install>/api/eid/callback` 注册为重定向 URI。
2. 在**设置 → BankID 与电子身份**中，开启**通过 TIC Identity 使用 BankID**，并输入租户名称（如 `https://id.tic.io/<tenant>` 中的部分）、客户端 ID 和客户端密钥。

只要使用你自己证书的 BankID 处于关闭状态，就会使用 TIC。OpenSign 只信任 TIC 的 `nin` 声明中的瑞典个人身份号码，并要求它有效。

## Freja eID

1. 在**设置 → BankID 与电子身份**中，开启 **Freja eID**。测试时请使用**使用 Freja 测试环境**。
2. 上传来自 Freja 的**客户端证书**（`.pfx` 文件）及其密码。
3. 添加 **Freja 结果签名证书**。OpenSign 会拒绝任何其签名无法通过该证书校验的结果。

签署人在 Freja 应用中确认。

## 通过代理使用其他北欧电子身份

Idura（Criipto）或 Signicat 这样的 OpenID Connect 代理可以接入挪威和丹麦的 BankID、MitID、芬兰的银行身份等。

1. 在代理处创建一个应用，并把 `https://<your-install>/api/eid/callback` 注册为重定向 URI。
2. 在**设置 → BankID 与电子身份**中，开启**电子身份代理（OpenID Connect）**，并输入**颁发者 URL**、**客户端 ID** 和**客户端密钥**。
3. 也可以设置**电子身份选择（acr_values）**来指定某一种电子身份，例如 `urn:grn:authn:no:bankid`。留空则由签署人在代理处选择。

签署人会被送到代理处再返回。OpenSign 使用带 PKCE、state 和 nonce 的授权码流程，并检查 ID 令牌的签名、颁发者、受众和过期时间。

验证必须在其开始的浏览器中完成：一个短期 cookie 把两者关联起来，TIC Identity 同样如此，从其他任何地方返回的应答都会被拒绝并记录在审计日志中。请对你的 OpenSign 地址保持启用 cookie。

当签署页面嵌入到其他网站中时，无法在框架内设置 cookie。此时签署人会得到一个在你的 OpenSign 地址上的窗口，它会说明这次验证是针对哪份文档的，签署人按下按钮后才会继续前往代理。这只适用于采用链接投递的参与方，并且要求该实例允许嵌入。

## 会记录什么

对于每次身份验证，OpenSign 会保存方式、电子身份返回的姓名和（掩码后的）个人身份号码、时间、IP 地址和浏览器。电子身份证据加密存储。它会出现在审计日志以及封印后 PDF 的证据页上。参见 [封印 PDF 与证据](sealed-pdfs.md)。
